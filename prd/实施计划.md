# 嘉里大通 Helpdesk 实施计划

> 产品定位：Service Desk / Helpdesk 平台，非云平台运维工具
> 核心流程：Service Catalog → TicketTemplate → Service Request → Ticket（ITIL 标准）

## 已完成

### Phase 1 — 基础设施

- [x] TicketCategory 层级树（82条，覆盖 ACC/EUC/COL/NET 四大域）
- [x] CI Type `business_system`（软件资产类型）
- [x] 初始化管道接入（`ProductionInitializers` + `SeedAll`）

### Phase 2 — 模板与表单（部分完成）

- [x] 4 个 TicketTemplate（账号申请/业务系统服务申请/故障报修/通用服务申请）
- [x] 25 个 FieldDefinition（覆盖 select/text/textarea/number/date/file）
- [x] 种子数据写入 + API 可查询

---

## 待实施

### P0：创建页 Service Catalog 驱动改造

**目标**：创建页从"平铺 24 种类型"改为"Service Catalog 三级分类 → 服务项 → 模板表单"

**当前问题**：
- `ticket-type-presets.ts` 的 12 个静态预设（K8S/DDL/GitLab 等）与 Helpdesk 无关
- 数据库 4 个 TicketTemplate 已正确但创建页未优先展示
- FieldDefinition 随模板存储但创建页不加载

**改造内容**：

| 层面 | 变更 | 文件 |
|------|------|------|
| 后端 | 新增 API：按 category_id 查询关联的 TicketTemplate + FieldDefinition | `handlers/ticket/` 或复用现有 `/tickets/templates` |
| 后端 | 新增 API：返回 TicketCategory 树 + 叶子节点关联的服务项列表 | `controller/` 或 `handlers/` |
| 前端 | 创建页重构：左侧展示 TicketCategory 树，右侧加载选中分类下的模板 | `app/(main)/tickets/create/page.tsx` |
| 前端 | 选中模板后加载 FieldDefinition 渲染自定义表单 | 同文件 |
| 前端 | 提交时关联 `templateId` + `customFieldValues` 结构 | 同文件 |

**用户流程**：

```
① 选择服务分类（左侧树）
    账号与访问服务 (ACC)
    ├── AD与基础账号
    │   ├── AD账号新建
    │   └── AD账号停用
    ├── 认证与登录支持
    │   ├── 密码重置/解锁
    │   ├── MFA绑定/重置
    │   └── 企业账号登录异常
    ├── 特权与临时权限
    └── 账号生命周期管理

② 点击服务项 → 加载对应 TicketTemplate
    模板：账号申请
    字段：
    ┌─────────────────────────────┐
    │ 账号类型: [AD账号 ▼]        │
    │ 操作类型: [新增/开通 ▼]     │
    │ 申请人姓名: [__________]    │
    │ 账号/工号: [__________]     │
    │ 所属部门: [__________]      │
    │ 申请原因: [__________]      │
    │ 附件: [📎 上传申请表]       │
    └─────────────────────────────┘
    + 标题: [_______________]  (可选填)
    + 详细描述: [_______________]  (可选填)
    + 优先级: [中 ▼]

③ 提交 → 创建 Service Request → 生成 Ticket
```

### P1：静态预设降级

**目标**：保留 Cloud Ops 能力但不干扰 Helpdesk 主流程

| 变更 | 说明 |
|------|------|
| `ticket-type-presets.ts` | 保留文件，但所有预设分类改为"运维操作(Cloud Ops)"，在创建页默认折叠 |
| `ticket_types` 表 | 保留 12 条记录，不作清理（向后兼容） |
| 创建页 | P0 改造后，静态预设作为"其他类型"入口，折叠显示 |

---

### P2：Service Catalog 独立浏览页

**目标**：用户可浏览完整服务目录，查看服务项详情，直接发起请求

| 变更 | 说明 |
|------|------|
| 新页面 `/service-catalog` | 按分类展示所有服务项，支持搜索、过滤 |
| 服务项详情 | 展示服务定义、SLA、审批要求、关联表单 |
| 一键创建 | 从服务目录直接跳转到创建页并预选服务项 |

---

### P3：创建页分类标签对齐

**目标**：分类筛选项从"技术支持/账户问题/系统故障"改为 ACC/EUC/COL/NET/BUS

| 变更 | 说明 |
|------|------|
| 前端 `ticketTypeCategories` | 移除或改为从 API 动态加载 TicketCategory 树的一级节点 |
| `ticket-type-presets.ts` | 不删除但不再作为分类标签来源 |

---

### Phase 3：Email Connector

| 阶段 | 能力 | 说明 |
|------|------|------|
| **P0** | IMAP 拉取 + 原始邮件进 description | 最小可用 — 复刻旧系统邮件开单能力 |
| **P1** | 发件人匹配 User + 附件自动挂载 | 提升数据质量 |
| **P2** | 主题规则匹配 Service Catalog + 自动分类 | 减少人工分类 |
| **P3** | LLM 字段提取 + HTML 清洗 | 结构化数据填充到自定义字段 |
