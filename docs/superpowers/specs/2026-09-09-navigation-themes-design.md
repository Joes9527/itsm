## 1. 目标与范围

将现有固定深灰导航、白色胶囊控件、各自定义的字体和间距统一为两套全站主题：A 统一浅色、C 统一深色。两套主题共享结构、尺寸、排版和交互，切换时不产生布局位移。

按用户后续确认，原业务内容区 backlog 合并进本阶段：统一设计、分批实现、整体验收。`/tickets` 和 `/service-catalog` 是两类样板，分别验证表格与卡片场景；实施计划须盘点其余业务路由的共用组件及局部硬编码覆盖，形成迁移清单，不把仅两页通过当作全站完成。预览中的工单数据、服务与 SLA、菜单分组均为示例，不成为新增产品数据或权限规则。

“全站”覆盖应用中已交付的用户可见路由：登录/注册等认证入口、门户、各角色工作台、管理页，以及业务列表、详情、创建和编辑页。统一这些页面的主题、排版和通用组件外观，保留各自布局及操作流程，不把控制台侧栏加到门户或认证页。图表、拓扑、流程与富文本编辑器纳入主题可读性检查，保留现有专业图形、语义色和编辑行为，不在本阶段重新设计可视化内容。

实施计划必须在生产代码修改前列出路由—实际布局入口—共用组件—局部样式—验证状态清单，逐项标记“需迁移”或“已符合并验证”。开发演示/测试专用页面可作为非交付项，但须明确列出依据。不能把难以迁移的用户页面直接改列例外；新增范围例外需由用户决定。全部纳入项完成主题检查、共享状态组件验收及所属页面类型的代表性交互验证，才能声明全站完成。

不改变后端接口、数据库、领域规则、RBAC、租户边界、菜单权限、工作台权限和路由。动态菜单仍由后端提供；不得将预览里的示例菜单硬编码进产品。

## 2. 已选方案与取舍

- A（默认）：白色顶栏和侧栏，细边界、深灰文字、浅橙选中背景。视觉轻，适合长时间工作。
- C：深灰顶栏和侧栏连成整体，浅色文字、透明浅色交互背景、暖橙选中强调。保留深色气质，消除白色控件突兀感。
- B（深侧栏、浅顶栏）不作为第三种主题实现，避免增加无需求的主题配置。

两套导航都取消底部橙色流光线、强阴影和大面积白色胶囊。保留真实品牌标识，不把预览的占位“IT”图标替换成正式 Logo。

辅助文字在预览基础上适度加深，保证小字号可读性。除用户明确指定的橙底白字主按钮外，普通文字与实际背景对比度至少 4.5:1；浅色主题中品牌色小字不足时使用深色文字并保留橙色图标、边线或选中指示，不修改品牌基础色。键盘焦点使用清晰轮廓，选中态同时通过背景与字重表达。

具体规则：A 的导航选中文字、分类/页签选中文字与行内操作文字使用 `#354153`，橙色用于指示线、背景和图标；C 对应强调文字仅在实际背景对比度达到 4.5:1 时使用 `#F06820`，次级表面或叠加选中背景不足时使用 `#E3E7EE`，保留橙色指示。橙色主按钮在 A/C 中均使用白字，默认对比度约 3.13:1；这是用户最新视觉要求对先前深色按钮文字规则的替代，不宣称该组合满足普通字号 4.5:1。主按钮 hover 使用 7% 黑色内叠层，active 使用基础橙色加内侧边线，交互状态保持白字。焦点采用深色外轮廓（A）或浅色外轮廓（C）加品牌内边线，使其在不同表面上可见。

## 4. 顶栏结构

左侧保留展开/收起控制、现有品牌或面包屑显示规则。右侧保留搜索、通知、主题、语言、工作台切换、用户菜单等当前可用入口；若真实代码按权限或配置显示额外入口，也必须保留。

搜索框使用低对比背景与细边框，桌面宽约 175px。快捷键保留现有 Ctrl/Cmd+K 行为，提示按平台显示。工作台入口采用透明背景、图标、名称和下拉箭头；用户入口采用圆头像、单行姓名与箭头。顶栏不再显示第二行角色标签，角色信息保留在现有用户菜单等详情位置。

通知、语言、用户等弹出层沿用现有组件与业务逻辑，颜色应跟随已解析主题，不另建一套弹出层系统。长姓名和工作台名允许省略，悬停或可访问名称可读取完整内容。

## 5. 侧栏与响应式

保留后端返回的菜单名称、顺序、分组、子菜单和权限过滤。子菜单沿用展开行为和路由选中逻辑，缩进表达层级，文字与图标统一规格。已有底部信息区域按同一排版和配色适配，不新增管理入口或重排菜单。

实际生效的控制台入口是 `src/app/(main)/layout.tsx`，不是 `components/layout/AppLayout.tsx`。桌面收起行为保持完全隐藏（宽度 0），不新增图标轨道；展开宽度 224px，内容左偏移同步。当前主布局使用固定侧栏加遮罩，不是 Drawer；本阶段沿用该呈现结构，不另建抽屉实现。窄屏展开时侧栏覆盖内容、内容偏移为 0；点击遮罩、选择目的菜单或按 Escape 关闭，并将焦点返回开关；展开期间焦点限制在导航区域，背景内容不可交互。

控制台移动布局以 `<768px` 为唯一断点，主布局判断与 Sider 自动折叠使用同一配置值（Ant Design `md`）。从桌面进入移动范围时收起侧栏；返回桌面不自动改变当前收起状态。1200px 以下收紧工具间距和搜索宽度；992px 以下只紧凑化顶栏（搜索图标、缩短名称），不改变侧栏定位或内容偏移。768px 以下将通知、语言、主题收纳到“更多”菜单，保留侧栏开关、搜索、工作台切换和用户入口。门户分支继续无侧栏且不呈现无效的侧栏开关。验证 390/768/1024/1440px，以及 767/768、991/992px 两组边界，无溢出、遮挡、焦点丢失或侧栏与内容错位。

## 6. 主题状态与组件边界

复用 `src/lib/design-system/theme.tsx` 中的 ThemeProvider 和 `itsm-theme` 存储键，以及 `ThemeHtmlClassSync` 的主题同步。不创建独立导航主题 store 或第二个存储键。

没有已保存偏好时默认 `light`。有效的 `light`、`dark`、`system` 历史偏好继续有效；`system` 根据操作系统解析成 A 或 C。顶栏主题按钮根据当前解析结果调用既有 `setMode`：浅色切深色，深色切浅色，不再从该按钮循环进入 system。其他已有设置入口的 system 支持保留。

读取偏好完成后才能写入，避免初次挂载默认值覆盖已存值。存储不可用时仍能在本次会话切换；非法存储值回到默认浅色，不导致渲染错误。刷新保持用户选择，初始恢复不出现可见的错误主题闪烁，SSR 与客户端不产生 hydration 报错。

首屏方案：在根布局首帧绘制前通过同一偏好解析规则设置根主题标记与 color-scheme；Provider 恢复偏好期间不渲染依赖错误默认主题的控件，保留中性的结构占位，恢复后由同一状态驱动 Ant Design 和 CSS。不通过新增存储键、弱化 CSP 或扩大 hydration 警告抑制范围解决闪烁。登录/注册页的静态浅色 ConfigProvider 覆盖必须解除或改为继承已解析主题，验证保存深色偏好后登出、登录和跳转的连续表现。

组件职责：

- `header/Header.tsx` 及子组件负责顶栏呈现、现有动作入口和主题按钮交互。
- `sidebar/Sidebar.tsx`、`MenuItems.tsx` 负责真实菜单呈现，保留加载和失败状态。
- 共用语义变量负责字体、颜色、控件尺寸；在现有设计系统中定义一次，由导航、页面、表格、卡片、按钮与弹出层消费。Ant Design 主题配置和 CSS 变量须读取同一组权威色值，避免两套主题定义。
- `layout.config.ts` 及实际布局调用方负责一致的高度、侧栏宽度和内容偏移；清除受影响路径上冲突的 56/64px、256px 硬编码。

目前布局配置中把 64px 作为特定设计公式并进行断言。实施时应把本次明确的 60px 产品规格更新到相应说明与验证，不保留错误告警；不因此扩大为全站布局重构。

`components/layout/Header.tsx` 与 `Sidebar.tsx` 当前是重导出入口，真实实现位于子目录。修改真实实现，不复制一份新导航实现。移除受影响组件中被语义变量替代的冲突样式，不做无关文件迁移。

计划须明确现有 `lib/design-system/colors.ts`、`design-system/tokens/index.ts`、`theme-variables.css`、`globals.css`、`generateCSSVariables()` 与 Tailwind 颜色入口的保留/派生/移除关系。只保留一个可手工维护的语义值来源，其余由它生成或引用；如保留生成产物，应有一致性检查。不得以额外覆盖层长期维持冲突主题。RootLayout 的字体声明与 Ant Design 字体配置也要消费同一字体定义，避免仅导航成功换字体。

## 7. 数据流与错误处理

用户点击主题按钮 → 现有主题上下文更新 → 已有全局主题同步与导航变量切换 → 本地偏好保存。此流程不请求后端。

菜单加载、失败、空状态继续遵守现有 fail-closed 行为，不以样例菜单兜底。搜索、通知、登出和工作台切换的错误反馈继续使用原有路径。样式修改必须覆盖加载、禁用、选中、展开、焦点和弹出层状态，不以隐藏错误来改善外观。

## 9. 同阶段业务内容区设计

状态：已纳入本阶段，完整页面视觉和书面设计已确认。

业务内容区与导航共用 A/C 主题及品牌色，按以下规格统一：

- 页面背景：浅灰/深灰页面底色与卡片表面形成一层清晰差异；桌面内容内距 24–28px，窄屏 16px。避免多个白底容器相互嵌套形成多重边框。
- 排版：沿用第 3 节字体栈。页面标题 24px/600，卡片标题 15px/600，正文及表格 13px，描述与筛选提示 12px，表头及辅助标签 11px，统计值 26px/600。
- 业务表格：细横向分隔线、低对比表头、轻悬停和浅橙选中背景；单行行高约 48px，编号加标题等双行约 64px。保留真实列、排序、分页、选择和操作，窄屏仅在表格容器内横向滚动。
- 卡片：8px 圆角、1px 细边框、16–18px 内距、14px 网格间距，不用重阴影。统计卡片淡化装饰色；服务卡片用平面线性图标，标题、描述、审批要求及交付信息分层，底部操作对齐。
- 业务按钮：常规 34px 高/13px 字号，小按钮 29px 高/12px 字号，6px 圆角。主要操作使用 `#F06820`，次要操作使用主题表面与细边框，行内操作使用轻量文字入口。禁用、加载、悬停及键盘焦点可区分，保留原交互逻辑。

工单样板保留统计、列表/看板/分析入口、高级搜索与表格动作，不新增统计能力。目录样板保留统计、动态分类、搜索、高级筛选（审批类型与排序）、卡片/列表切换、详情与现有授权操作。预览为视觉样板，未模拟全部行为不代表正式页面可删除这些能力。

服务卡片桌面根据容器宽度显示 3–4 列，中屏 2 列、手机 1 列，单卡目标最小宽度约 240px。目录列表模式窄屏可换行；筛选和页面操作允许换行，文字不被固定高度裁切。预览为了窄面板观看而缩放桌面画布，正式应用不能用全页缩放替代响应式。

加载、错误、空列表、筛选无结果、按钮禁用/加载和长文本均须覆盖 A/C。迁移业务区域时只改变呈现，不重新解释审批要求、SLA、权限或服务分类。分批实现顺序为主题基础、导航、样板页、其余清单页面、整体回归，均属于同一阶段。
