# SSLVPN 手工全生命周期测试手册设计

状态：accepted，2026-09-14；范围已由维护者在会话中确认。此状态表示文档方案获准，不表示运行环境或业务验收通过。

## 目标和读者

供维护者在 WSL 开发环境按角色手工验证 SSLVPN 场景，覆盖 ITSM 与 KAF 部署准备、自定义字段表单、BPMN、WorkItem 生命周期、邮件建单/自动回复和结果查找。交付可重复执行的操作手册，并修订现有相关文档。

## 方案选择

采用一份业务全流程主手册，引用并修订既有部署手册，分模块用例补充适用边界与对应入口。只扩写部署手册会让业务测试被部署命令淹没；完全重写所有模块用例会扩大范围并造成重复维护。选定方案保留原目录与用例编号。

## 内容结构

1. 环境、版本、账号、测试对象与执行记录。
2. WSL 已部署环境核验和必要时的 ITSM/KAF/Worker 部署路线。
3. 五种可配置自定义字段、保存回读、请求校验、字段快照、版本变更和全程回显。
4. 双级审批 BPMN、policy 引用、发布激活和目录绑定。
5. ITSM 表单及 KAF 对话两个受理入口，拒绝和正常履约路径。
6. 同一 WorkItem 的查询、评论、附件、分派、审批历史、流程状态、完成与关闭检查。
7. 取消、未知结果、越权、重复提交、恢复与证据记录。
8. 真实邮件客户端发信、自动建单确认、原会话回复、附件、通知和内部备注保密。

每个步骤给出角色、入口、输入、预期和证据；用户补充确认：业务操作与验收仅通过 UI；不执行管理员 API 作为补验。运维部署是独立前置，当前缺少 UI 入口的能力记录 BLOCKED/FAIL。此约束取代早期混合验证描述。

## 约束

- 本次只改文档；不执行 WSL 部署、迁移、审批或真实 Graph 授权。
- 环境事实按日期和提交记录，不将 2026-09-08 快照当成当前实测。
- WorkItem 是共享身份，SSLVPN Requested Item 是专业执行记录；不创建第二张 Ticket 串接审批。
- 审批入口以 `/approvals` 为准；`/workflow/ticket-approval` 是设计器。
- 自定义字段单独成章，贯穿提交、审批、履约和历史查看。
- 真实授权只针对环境负责人确认的 Dev 对象；不使用旧合成申请或改表推动状态。
- 主仓库与其他 Agent 的文件保留；修改位于独立文档 worktree。

## 功能操作顺序修订（2026-09-14，按用户纠正）

用户明确要求流程拆到具体功能，并列出每个功能的操作和数据。替换先前故事分幕方案：主手册 OP00–OP22 按依赖顺序排列，邮件手册 EM01–EM12 单列，每项明确账号、菜单、输入控件、填写数据、保存动作与检查结果。SSLVPN 仅提供贯穿流程的测试数据。

自定义字段逐行列出字段名、标签、类型、必填和选项；用户主角色与审批组成员分别操作；流程版本、审批链查看和目录绑定分别记录；两级审批拆为查找、查看字段、领取、输入意见、确认和回读。Agent 以功能子步骤续跑，替换场景/幕交接方式。

仍保留 UI 验收边界、C-FORM 与 C-EXEC 的区别和缺入口的 BLOCKED/FAIL；邮件通用工单不自动变成权限申请。操作数据不预填当前账号密码、环境状态或实际测试结果。
