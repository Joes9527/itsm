## 1. 目标与权威来源

交付一个在 WSL 稳定可访问、包含最新 WorkItem 能力和全站明暗主题、通过完整范围内业务验收的候选版本。交付包括固定源码与构建指纹、访问及启停入口、数据来源和隔离清单、验收证据、恢复路径与明确限制。

遵循 [AGENTS.md](../../../AGENTS.md)、[工程协作规范](../../agent-engineering-governance.md) 和 [开发指南](../../DEVELOPMENT_GUIDE.md)。本设计定义本轮交付边界，不改变 WorkItem 字段所有权、专业生命周期、RBAC、tenant/MSP、BPMN、SLA 或迁移契约，不取代既有专业设计。

维护者已确认：以 WSL 可验收候选版本为终点；使用现用业务库备份副本；保留旧结构；完整业务验收使用真实候选应用、数据库及 Worker，企业外部动作另行受控验收。

## 2. 方案选择与范围

选择“先集成已有成果，在隔离环境验收，再形成稳定候选入口”。相比先扩展 backlog，该方案尽早验证已有能力的组合；相比先合并基础设施，避免同时改变应用、数据迁移机制和共享存储拓扑。

纳入：版本依赖核对、业务与主题集成、直接影响执行的文档纠偏、备份副本恢复与兼容性盘点、必要结构准备和普通迁移、业务与主题验收、隔离候选运行和交接。

排除：R(038) 旧结构退役、I2 通用在途流程退役实现、物理清理、历史业务回填、Change 多 WorkOrder、首响新口径、WSL 基础设施合并、生产部署、真实邮件/VPN/企业连接器写入及既有 worktree 清理。已有成果不重新立项开发；集成引入的回归必须在本轮修复。

仓库合并与候选环境发布是不同动作：可从固定的候选分支构建和验收；本设计不要求先合并 main，也不构成推送或合并既有 PR 的操作授权。

## 4. 运行边界与数据流

候选环境由固定版本前端、API、所需 Worker、任务专属 PostgreSQL/Redis/对象及附件存储组成。复用现有应用和编排机制，不引入第二套业务服务或任务状态机。

数据流：现用源配置与实际连接的只读核验 → 受保护备份 → 独立候选存储恢复 → 只读迁移准入 → P(037，按真实目标状态判断) → 获准普通迁移 → API 及页面验收 → 隔离 Worker 验收 → 稳定入口。

真实企业出站在网络及凭据边界阻断。应用凭据不得有源库、源 Redis、源 bucket 或真实企业写入权限；候选端口不得覆盖旧监听。资源清单记录所有者、精确名称、版本、端口、逻辑数据位置和凭据来源，不记录秘密。

优先使用任务专属存储实例和卷；若某存储复用共享实例，必须证明角色及数据隔离、资源预算和禁止全局清理的边界，并将该步骤标记为共享环境变更，按治理串行执行。Redis 单独 DB 编号本身不能证明完整隔离。

## 5. 备份副本与历史任务保全

不从库名推定现用库。根据实际启动入口、配置来源、API/Worker 连接和迁移账本确定源；多个活动数据集不能静默合并，必须形成源映射并由维护者核对。

备份覆盖本轮旅程依赖的业务记录、流程、审计、回执、序列、角色/权限元数据和附件对象；需要的 Redis 状态单独定义恢复语义。跨存储一致性须记录时间边界与核验方法；在线备份不能声称跨服务原子一致。若取得一致副本必须暂停源写入，先准备影响清单、恢复措施和具体窗口，不能因设计确认而任意停止源服务。

备份、对象内容和配置保存在受保护的任务目录，不提交到 Git。恢复完成核对记录数量及关键内容摘要、序列、引用和角色/RLS。不得将带源超级用户权限的账号直接用作候选业务身份，也不得自动继承企业秘密。

候选消费者默认停止。复制的历史 pending/processing/outbox、nonce、租约和锁不得被当作新的执行授权，不清空历史任务、不伪造完成回执。开启任何 Worker 前，必须证明它仅消费本任务允许的记录，并以现有配置/作用域机制隔离历史队列；若现有机制不能做到，相关 Worker 保持停止，该验收项明确阻塞并进入单独设计，不临时硬编码绕过。

TTL 保持绝对到期语义，不复活过期凭据。测试创建新记录并使用可归属标识；原历史数据保留用于只读对账和兼容性验证，不执行历史业务 backfill。

## 6. 迁移、失败与恢复

迁移沿用唯一目录、历史 checksum、真实回执和受控准入；未知版本、旧账本漂移、未注册 SQL、未知依赖或权限不符时停止。禁止 fresh/reset、伪造 022/027 回执、手动执行未注册 RCA SQL、Ent overlay、双写及绕过检查。

正确顺序为：只读目标分类及证据准备 → 必要 P 结构准备 → 普通迁移 → 完整业务 V1。P 事务内仅核验本阶段结构及所需角色/RLS，不提前调用依赖后续迁移字段的业务旅程。P 已提交而普通迁移失败时保留真实 P 回执，不能宣布应用就绪。

本轮不执行 R(038)。旧结构仅作为受保护历史保留，新业务代码维持唯一权威读写。I2 不阻塞候选代码集成，但其限制必须在交付中披露，不宣称一般 P 前活动流程可退役。

独立候选恢复失败时保留证据并停止候选写入；依据受控备份重建任务专属目标，不能恢复覆盖源实例或自动销毁其他资源。候选开始接收人工写入后，回退前先保全新增数据库、对象、队列和外部边界记录；不得用较旧快照声称零损失。重启保留固定构建和配置来源，防止启动到另一 worktree。

## 7. 三道验收门禁

### G1 版本集成

- 建立两来源受影响测试基线；集成后后端构建、前端类型检查/构建、契约、主题生成一致性及定向回归通过。
- 逐项核对重叠文件，证明主题未覆盖业务修复，业务页面未重新引入第二套主题来源。
- CI 检查为空或 Git 可合并均不构成成功证据。测试数量、skip、既有失败、实际构建指纹分别记录。
- WorkItem、迁移、权限等变更由独立审查者或维护者复核，实现者不作为唯一验收者。

### G2 数据与业务

- 候选备份真实恢复通过；源/目标身份、历史数据和附件引用核验；受限非 owner 角色验证租户/MSP/RBAC，禁止用超级用户测试代替。
- Incident 分派/转派/开始/解决/重开；Problem 调查、修复验证和生命周期；Change 审批、任务、实施与关闭；generic/Requested Item 的共享能力及批准范围内流程通过。
- 核验 WorkItem 身份/版本、并发冲突、关系、SLA 周期、审计、附件与通知状态，重复请求不产生重复业务效果。
- BPMN/API/Worker 使用真实候选运行入口，保留失败、重试、幂等和持久化断言。未执行的 Worker 项不能计为通过。
- 双主题及持久化、移动导航、关键弹层/表单、列表/详情/创建/编辑页与业务组合回归通过；执行已有专项浏览器套件。144 路由 fixture 外观证据可复用为历史基线，不替代本候选版本真实后端验收。
- 不继承破坏性测试脚本对默认库的假设；需独立 fixture 的自动化另用任务测试库，人工候选库与可重置测试库分开。
- 真实邮件、VPN 加组等企业写入不执行。验证出站阻断以及可观察的 blocked/pending/error，不能把被阻断的外部动作标记为成功。需要成功投递协议测试时使用独立测试接收端，并明确其不是真实企业履约。

### G3 稳定运行与交接

- 提供固定访问 URL、版本 SHA/构建摘要、配置来源、资源清单、启停/恢复入口和后台消费者归属。
- 在隔离候选上执行受控重启，验证 API 就绪、前端关键旅程及允许的消费者恢复；不触发源服务重启。
- 重启后连续观察至少 60 分钟，记录就绪、错误、数据库连接、队列年龄和持久化状态；持续流量采用低频只读探测。未满足门禁的消费者保持阻断并披露。
- 维护者完成代表性页面与业务旅程验收；三道门禁均通过后，才将设计标记 implemented。外部履约、R 和生产上线仍明确未验收。

## 8. 风险与任务拆分

| 顺序 | 任务 | 主要输出与停止条件 |
| --- | --- | --- |
| 1 | 基线和文档纠偏 | 依赖图、入口状态、迁移顺序；不大规模整理历史文档 |
| 2 | 候选代码集成 | 固定版本及 G1 证据；冲突或回归未解决不进入交付 |
| 3 | 源映射和隔离恢复 | 精确资源/消费者清单与恢复证据；无法防止历史重放则阻断 Worker |
| 4 | 迁移和业务验收 | P/普通迁移证据与 G2；未注册 RCA 依赖等真实阻塞不手工绕过 |
| 5 | WSL 稳定候选 | G3、入口和交接记录；源环境保持保全 |

Redis 冷启动撤销必须验证撤销状态不丢失或鉴权明确失败。若当前代码不能满足，作为本轮安全阻塞提出有界修复设计。HMAC provider 默认不启用；若候选旅程必须启用，则使用候选专属身份并补齐恢复/nonce 防重放验证。未验证能力不能由 backlog 标签豁免。

不自动创建更多开发波次：I2、物理清理、多 WorkOrder、首响新口径和基础设施整合保持独立任务。最终交接分别报告设计接受、代码完成、隔离验证、候选运行、main 合并、真实外部动作及生产部署状态。

## 9. 书面设计审阅与后续

本设计确认前不开始实施。维护者审阅时重点核对新增操作细节：候选独立资源、历史任务消费门禁、60 分钟观察和安全阻塞条件。确认后生成逐项实施计划，补齐实际资源准入及最小测试命令，再按已确认边界执行；真实源停写或企业外部动作仍需对应具体操作范围。
