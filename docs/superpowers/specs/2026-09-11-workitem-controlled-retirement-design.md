## 1. 决策来源与目标

维护者已同意“保留历史账本，拆分结构准备与受控退役”。本设计细化该决定，继承[后续设计](2026-09-11-workitem-convergence-next-stage-design.md)、[业务决策记录](2026-09-11-workitem-convergence-development-input.md)与[运行手册](../../deployment/workitem-convergence-cutover.md)。B1–B5、F1–F3、V1的已验证成果保留，不重新实现。

采用现有Migrator、RegisteredMigrations、LegacyMigrations和schema_migrations，不引入第二套迁移执行器或审批引擎。历史SQL与checksum保持不变；未实际执行的旧迁移不能写成applied；旧结构保留期间，运行代码只读写WorkItem新路径。

备选方案为重新建立完整安装基线及升级体系。它涉及全部历史版本，不符合本轮最小范围，因此不采用。直接改022/027 SQL、伪造旧回执、跳过checksum或继续使用CASCADE均不符合已确认约束。

## 3. 同一目录内的三类职责

| 类别 | 职责 | 正常应用启动 |
|---|---|---|
| 历史识别 | 022/027移入LegacyMigrations，保留原SQL解析、checksum、版本和已有回执；停止主动重放 | 只识别和校验，不执行 |
| 结构准备P | 从022/027拆出新路径必要的校验、约束、RLS和保留列写入条件；不删除退役清单对象 | P及获准后续迁移完成、完整业务验收通过后才允许新应用就绪 |
| 受控退役R | 在观察与恢复证据满足后，按精确清单删除旧结构并写入真实新回执 | 永不自动执行 |

P、R是设计中的逻辑名称。实施计划必须核对当时目录后分配不可重复的新版本号，不提前占用可能被其他任务使用的编号。两者仍在唯一注册目录、SQL解析和schema_migrations中登记。

目录增加明确的阶段及前置条件元数据；已知阶段限定为普通结构迁移、WorkItem准备、受控退役，未知阶段拒绝。只支持本方案所需的固定依赖，不建设任意工作流或另一套调度系统。

bootstrap、migrate up/down、reset、status、dry-run及直接ApplyMigration/RollbackMigration共用规划与门禁。所有回退请求必须检查反向依赖；存在已提交P/R或其他后继时，拒绝撤销其前置迁移。reset必须在首个写入前验证整个计划，不得跳过不可逆阶段后继续撤销依赖。默认运行遇到缺少P时报告需受控准备，不能自动跳过后继续启动。R保持明确pending_manual状态，不能显示“全部迁移已完成”；R尚未执行不阻止已经通过P和验收的新路径运行。

## 4. 顺序与账本真实性

固定顺序为：只读盘点 → 既有前置结构满足 → P事务内结构验证并提交 → 剩余获准普通迁移 → 完整业务验收 → 应用就绪与观察 → R。

只读目标分类、旧账本及阶段检查必须在Prepare、CreateSchema、EnsureMigrationsTable升级或其他任何结构/数据写入之前完成；拒绝时这些写入函数不得被调用。账本缺失不能自动判为新环境：只有明确核验为空且获准的新建目标才能进入规范基础结构创建路径。已有目标缺账本或账本结构无法识别则阻断。

P必须先于原依赖022效果的后续迁移。版本号用于不可变身份，不再靠“新编号只能最后运行”推定依赖顺序。普通active迁移之间仍保留原连续前缀检查；P/R单独按目录声明的前置条件核验，不以移除全局校验解决插入阶段问题。

P的前置条件是原active流至021的有效前缀及所需基础表；已应用到更后版本的环境还要验证全部已有回执。P执行前禁止借Schema.Create或旧迁移补造、转换历史WorkItem数据。缺基础表、归属、编号、必要证据或遇到未审查DDL时阻断。

schema_migrations继续是执行事实的唯一账本。为新阶段回执增加可选的目录修订标识及执行证据摘要引用；旧回执不回填这些字段、不改时间或checksum。新P回执记录被识别的历史目录、操作人与目标、变更单、前置报告和准备结果摘要；R回执记录相应退役证据及结果。外部报告是证据附件，不能代替数据库回执或反向证明迁移已执行。

对于尚无P回执的环境，先按本次切换前的固定目录验证旧账本连续性，再进入转换；不得因为022/027被移到legacy，就把原来不合法的历史空洞自动合法化。有P回执的环境按新目录及阶段依赖验证。未知版本、重复、checksum变化、阶段缺失或回执/实际结构矛盾均拒绝。

| 环境画像 | 处理 |
|---|---|
| 新建空环境 | 创建规范基础schema并执行已审查前置结构；P验证后才继续。不得执行具有实际删除效果的历史SQL |
| 合法旧前缀，022/027尚未执行 | 校验旧前缀及保留数据，受控执行P；不补写022/027回执 |
| 022已执行、027未执行，或两者均已执行 | 校验真实旧回执并核对实际结构；执行新P的校验/必要准备并记录真实P回执，不重放旧SQL |
| 旧账本有空洞、checksum不符，或“已删除”对象异常重现 | 阻断并列出差异；本设计不提供清洗或重置账本工具 |
| 其他待执行旧迁移仍会删除本清单外对象 | 阻断并单独决定，不自动扩大V2范围 |

## 5. P：保留旧结构时让新路径真正可用

P在显式暂停相关写入和消费者的窗口执行；所有目标使用核验过的精确schema，不能沿search_path回落。

必要校验包括：一对一WorkItem归属、记录类、租户、重复或孤儿引用、公共编号、软删除范围及旧公共值与权威值的冲突。发现历史冲突只报告，不自动回填、映射或删除记录。

准备内容包括：

1. 为专业work_item_id建立并验证精确外键、唯一性及NOT NULL；遇到名称相同但定义不同的约束拒绝。
2. 同一事务退出已识别的旧租户策略，安装基于WorkItem的权威RLS；未知额外policy或grant必须先审查，不能把保留宽泛PERMISSIVE策略当成安全。
3. 保留旧表和旧列中的数据，但核查旧NOT NULL、默认值、CHECK、触发器或依赖是否会迫使新代码继续写旧字段。仅允许目录明确列出的约束/默认值调整；未知对象阻断，不增双写或填充触发器。
4. 在隔离演练中，以实际非owner、非super、非BYPASSRLS业务角色验证本阶段所需列的受限SQL创建、更新、查询和跨租户拒绝；不得依赖尚未执行的034等迁移字段或要求当前应用完整查询在P内通过。目标环境只做获准的结构核验，不植入测试数据。
5. 校验本阶段后置结构并与P回执在同一事务提交；失败全部回滚。

P提交后才执行获准后续普通迁移，再验证当前应用的三域完整创建/更新/查询、共享协作、Requested Item及V1旅程。完整业务验收失败时保持应用未就绪、禁止观察与R；保留真实P回执，不将后续失败伪装成P事务回滚，也不复制后续迁移到P。

P记录保留历史的基线范围与摘要。P前核对旧公共值与权威值的一致性；P后新路径会继续变化，旧列不得同步更新。因此R不再比较旧列与当前WorkItem是否相等：核对P时既有记录的保留值、备份与新路径审计连续性；新增记录的旧列可为空。当前受支持的业务删除仅为所属领域执行的WorkItem软删除，基础记录和专业扩展仍须保留，WorkItem的deleted_at、updated_at及version可按现有领域规则变化，不要求同步旧公共列。P基线中的原始记录若物理消失，R必须拒绝；不得仅凭HTTP DELETE审计或调用者声明将其解释为合法物理删除。物理清理及其原子、可验证的删除审计协议另行设计和批准后，才能扩展R的基线对账。未解释的保留值变化仍阻断。

保留数据不是运行fallback。P完成后，旧代码、旧消费者和旧列写路径必须退出。若后续完整验收发现新建记录仍依赖旧字段，则结构准备不满足运行准入，需要修复后重新验收；保留已提交P的真实执行记录，不能开始观察或宣称可运行。

## 6. R：证据绑定与精确删除

正常应用启动和普通migrate up不能调用R。受控模式复用同一Migrator，需要明确目标与独立环境准入；单一force/allow-delete布尔值不构成准入。

输入证据必须绑定：目标连接部署、数据库与schema、P及普通迁移回执、应用提交/镜像、预检结果、待删对象及依赖清单摘要、备份及恢复结果、V1旅程、观察范围与结果、操作者及环境变更单。观察时长与样本要求在该环境开始观察前确定，不以硬编码分钟数代替验收。

摘要用于检测报告变化，不代表审批真实性。执行者仍需既有运维身份和环境变更授权；不读取用户自行填写的“approved=true”来放行，不新增BPMN审批流程。

恢复写入后产生的新数据必须有最终可恢复备份或经验证的增量恢复能力。R执行前再次暂停写入/消费者、核对在途任务、生成最终恢复点并验证恢复完整性；只有观察前备份不能证明删除后的恢复能力。

执行协议：

1. 锁定目标及迁移执行互斥，固定精确schema，设置明确lock/statement超时；锁超时拒绝。
2. 在锁内重新读取账本、对象、约束/触发器/视图等依赖及数据完整性，比较获准清单；任一漂移均要求重新盘点，不复用陈旧报告。
3. 逐项删除[运行手册](../../deployment/workitem-convergence-cutover.md)列出的022/027对象，采用明确schema和RESTRICT。依赖对象本身也须逐项在获准清单中；禁止通配符、CASCADE或自动递归扩大删除。
4. 核对公共记录、编号、createdAt、专业证据与审计保持，旧对象按清单消失，新路径约束/RLS仍有效。
5. 删除与R回执同一事务提交。提交结果不明时先读取回执和结构，同键/同证据只返回原结果，不盲目重删。

同目标、同版本但不同SQL或证据摘要应冲突。首次执行就发现清单对象异常缺失且没有R回执时必须重新盘点，不能把IF EXISTS当作外部删除已被审计。全新环境本来没有旧对象时，以显式“清单为空”的核验结果记录R无删除完成，不伪造曾删除旧结构。

## 7. 恢复与历史边界

P和R各自事务内失败均回滚，失败输出归入操作证据；没有提交就不写成功回执。

P提交后的应用回滚先核验旧应用与当前schema/RLS是否兼容；不可仅替换二进制。R提交后不提供空表重建式down迁移，不删除账本回执来“回滚”。使用已验证恢复点协调数据库、应用、附件存储及消费者版本，并逐项核对备份后新写入和外部副作用。

恢复演练必须在R真正删除后的独立环境完成：恢复记录、数量和内容摘要、原始时间、关系、流程/审批/回调/审计/回执、附件对象及实际RLS，并重新跑业务旅程。此前只做过备份恢复的结果不能替代该演练。

历史Problem证据不补写、旧SLA不重算、关系不搬运、旧流程不自动取消。旧Change启动事件或缺冻结证据记录必须单独盘点处置；P/R不提供自动修复业务历史的功能。

## 8. 必需验证与完成标准

| 验证组 | 必须证明 |
|---|---|
| 目录与账本 | 两种目录状态、合法历史画像、未知/空洞/checksum/伪造阶段拒绝；bootstrap/CLI/直接调用结果一致 |
| 顺序 | 至021且缺034的画像可完成P结构验证；后续迁移及业务验收前应用不就绪；拒绝发生在Prepare/CreateSchema/账本升级前；P前不能越过依赖执行普通迁移；P后R待执行不误报失败或全部完成；其他破坏性历史DDL仍阻断 |
| 准备 | 保留旧数据、三域新写入不依赖旧列、RLS真实角色隔离、额外policy及未知约束拒绝 |
| 删除 | 有效证据允许精确删除；缺备份/未验证恢复/未观察/目标错配/清单漂移/未知依赖全部拒绝 |
| 原子与并发 | 直接回退/reset不能撤销已提交阶段依赖，拒绝时结构及账本不变；两执行者互斥、锁超时、DDL或回执失败回滚、响应丢失后重放不重复 |
| schema | 当前schema缺表、后续schema诱饵、同名约束以及跨schema依赖均不误改 |
| 完整恢复 | 观察期间及最后备份之后的新增数据演练，R后完整恢复与外部副作用补偿清单 |
| 业务 | 在P后保留旧结构、R后及恢复后三个时点验证V1与公共事实不变 |

只允许在隔离schema/database演练；不得改写已有运行环境以建测试数据。自动化检查通过不等于实际环境授权。

设计获批后，实施计划依次覆盖目录/阶段规划、P准备、R门禁与执行、完整恢复及三时点旅程；每批保留真实RED/GREEN与独立审查。最终仍分别报告代码完成、隔离演练完成、目标环境准入、部署、观察与退役，不合并为单一“完成”。

## 运行时只读准入边界（2026-09-11 Task 5 澄清）

部署独立配置专用 inspection role/connection；业务连接不复用 owner 凭据，也不获得全局历史证据读取权限。inspection role 仅获得同一目标 schema 中 schema_migrations 与 work_item_migration_evidence 的 SELECT，不得获得业务表读取、写入、ownership、grant option、角色继承/授予或 BYPASSRLS。P 在原始附件中固定该身份；既有附件不追加或重写。只有独立配置与原始回执一致的该角色可读取附件；其余新增 ACL 仍拒绝。

运行时连接以只读事务核验回执/附件摘要、受信任历史签名、当前结构及安全元数据；先比较业务与 inspection 连接的数据库、schema、服务器，再核对部署身份，完成后关闭 inspection 连接。运行时结构准入不执行受 RLS 过滤的全局业务行查询，不声称 FK 能证明所有 record_class 一致性。P/R 控制执行和锁内复核继续由受控运维身份执行完整归属、重复、类别、保留基线检查；完整业务验收另由三域及 Requested Item/V1 旅程证明。

空环境也必须在普通迁移至 021 后停在手工 P；P 后才继续普通迁移并准入就绪。已有目标不再运行 Ent/Prepare overlay，避免隐式补出后续普通结构。缺 P 或任一普通结构/回执时不得 reconcile/seed 或宣称就绪。
