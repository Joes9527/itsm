## 2. 目标与范围

### 目标

1. 页头一个刷新入口，正常内容区域没有重复刷新按钮。
2. 刷新不卸载已展示页面，不丢失草稿、编辑状态、当前 Tab 与展开状态。
3. 局部失败独立恢复；保存成功与随后读取失败分开反馈。
4. 当前任务突出有效动作，只读/空状态紧凑，历史任务独立折叠。
5. 保留已有权限、租户、请求归属、版本冲突和审计边界。

### 非目标

不增加申请人全流程视图、节点预测、轮询/WebSocket、新审批引擎、任务命令、数据库迁移、共享环境写入或全仓主题重构。不扩大任务可见范围，不按角色名或任务名推导动作，不增加领域状态机。无任务结果不等同于无流程或流程完成。

### 依赖和影响

生产影响限定 TicketDetail 及其现有共享读取/面板消费者、对应测试。共享组件影响范围须包含 WorkItemShell 等消费者，不因移除局部刷新而令其他页面失去既有刷新能力。页面之外的消费者在接入等价刷新入口前保持原体验；这属于按调用场景定义的呈现，不保留两套数据实现。

不要求新后端 API。若实施核验发现既有状态/授权契约不足，保持明确不可用状态并记录契约缺口，不以前端猜测补齐。开始实施时重查 main 和相关并行分支，避免覆盖后续任务分配/关系改造。

## 3. 已选择的方案

用户选择 B：统一现有详情体验。A（仅隐藏按钮）不能解决刷新卸载与数据协调问题；C（完整流程进展）需要更广的受控后端投影，另行设计。

### 3.1 统一刷新

- 页头提供带可访问名称的刷新控件，忙碌状态可见。Alt+R 与此入口使用同一刷新语义。
- 重新读取工单主体、已初始化的页面摘要及已加载子区域；未加载 Tab 保持按需读取，已加载但暂时隐藏的区域标记需要更新，最迟在重新显示前读取。
- 不预加载所有 Tab，不为了刷新而请求用户未获授权的资源，不触发业务写命令。
- 同一页面刷新批次内、同一资源和同一身份的并发读取合并，重复点击不制造请求风暴。
- 正常区域不显示局部刷新。首次读取失败或后台读取失败提供局部重试；只重读失败资源。
- 首次主体读取无数据时显示 Skeleton；同一工单后台刷新保留现有内容。临时主体读取失败保留旧内容并标明失败；明确认证/授权失效清理受保护内容。不能继续以通用全页 Skeleton 卸载子树。
- 统一入口汇总本批次已参与资源的结果；部分失败标注失败区域，不提示“全部更新成功”，也不把未加载资源计作刷新成功。

### 3.2 编辑与变更后读取

- 同一工单刷新不重建编辑表单、不覆盖用户输入，不重置评论草稿、Tab、展开状态或滚动容器。
- 提交沿用打开表单时的版本和已有幂等/不确定结果重试语义；刷新得到新版本不得静默替换未提交命令版本。
- 同一资源写入中不启动与其竞争的用户手动刷新；操作结束后以结果驱动重新读取。其他区域继续可用。
- 写入成功后的读取必须发生在该写入之后；不能复用写入前仍在进行的读取作为更新成功证据。已有旧响应隔离机制阻止写入前响应覆盖新数据。
- 评论写入后更新评论和父层计数；附件上传/删除后更新附件和计数。
- 领取/完成流程任务后更新任务、工单和已初始化的审批历史；未初始化消费者下次打开读取。避免将任一动作扩大为所有资源重取。
- “操作已完成，部分数据更新失败”仅在后端确认写入成功时显示。此时只重试读取，不诱导重复业务提交；提交结果不确定则沿用现有命令恢复机制。
- 切换工单/账号/租户及权限失效不适用保留旧草稿承诺：继续清理旧身份内容和编辑状态，迟到请求不得恢复它们。

### 3.3 当前任务与历史任务

| 数据状态 | 呈现 |
| --- | --- |
| 有后端允许执行的活动任务 | 默认展开当前任务，突出有效动作；并列任务保留各自操作，不臆造唯一下一步 |
| 有可见活动任务但无本区域可执行动作 | 紧凑只读摘要，可展开查看详情；审批仍链接已有审批中心 |
| 成功读取后无可见活动任务 | 一行“当前账号暂无可见的活动任务”；若有历史结果，保留历史入口 |
| 首次加载 | 局部加载状态，不先显示正常空状态 |
| 临时读取失败 | 保留已读结果并提示更新失败；操作仍遵循既有错误锁定条件 |
| 最终认证/授权拒绝 | 清理任务和相关弹窗，明确显示不可用状态，不伪装为空列表 |
| 未知任务/状态/输入要求 | 保留可见限制或错误，不推断可执行动作，不当作已完成 |

- 活动与历史分组使用同一批授权查询结果和既有后端状态语义；已完成/取消的可见记录置于默认折叠“历史任务”。不为了补全历史扩大查询权限或引入另一个历史账本。
- 保留当前后端返回的负责人及实际操作人区别，不从当前工单处理人反推历史负责人。
- 领取/完成严格依赖服务端 `uiActions`，服务端仍在命令时重新授权。审批、带必填表单任务、自动化任务使用其已有专用边界，不能空参数强行完成。
- 默认展开仅适用于首次展示或上下文切换；同一工单普通刷新保留用户的展开选择。任务变更通过计数/摘要可见，不强制打断操作。
- 复用现有主题 token 和响应式模式；不保留新面板中的硬编码白色作为此次调整后的主题方案。

## 4. 组件与数据职责

### 4.1 TicketDetail

负责当前工单身份、页面组合、主体首次加载/后台更新、统一入口和批次结果。新增协调代码沿职责边界从已过大的 TicketDetail 中提取为紧邻详情的局部 hook/context；不创建全局 Manager/事件总线/第二套缓存。

刷新协调只接入资源已有的 reload/失效能力。资源以身份和真实查询语义识别，卸载时退出协调，迟到的旧批次不能更新新页面的结果。协调状态只记录读取进度和错误归属，不保存第二份业务数据或统计。

### 4.2 业务面板与 useDetailResource

业务面板保留自己的 API adapter、业务读取、写入及计数回调。`useDetailResource` 继续承载身份、请求归属、旧响应隔离和拒绝清理；必要时在此收敛并发读取与结果回执，不在各面板再复制一套实现。

现有 reload 内部处理错误，不能仅凭 Promise 正常结束判断成功；实现必须提供可供协调识别的实际读取结果，并区分被上下文切换取消/废弃的结果。返回值只描述请求结果，不复制业务判断。

`DetailReadState` 在已接入统一刷新的详情区域仅呈现读取反馈和失败重试。其他调用场景显式选择已有正常刷新入口，避免无意改变全站共享组件行为。

### 4.3 审批历史单一来源

同一详情页面身份下只实例化一个审批决策历史读取来源，右侧摘要与审批 Tab 消费同一结果及读取状态。页面范围内共享，不建立跨工单/跨租户缓存。删除该页面原有重复读取路径；独立使用共享审批面板的其他页面继续在其自身页面范围拥有来源。

仅共享相同的 BPMN 审批决策记录。服务目录审批链、通知与流转历史不是同一业务概念，不因界面相似而合并。Tab 计数仅在语义对应时从同一结果派生，不混用可见任务数、决策条数与流程步骤数。

## 5. 验收标准

### 组件/集成回归

- 正常 Ticket 详情只有一个常驻刷新入口；错误区域出现局部重试，恢复后移除。
- 主体和每类参与资源各覆盖首次失败、后台失败、成功空态、权限拒绝、身份切换与旧响应到达。
- 全局刷新不重复请求同一审批决策；右侧摘要与审批 Tab 保持一致；未访问 Tab 不被强制预取。
- 全局与局部并发读取、写前读取/写后更新交错时，更新结果正确，不重复业务提交。
- 评论草稿、编辑输入、打开表单时的版本、当前 Tab、展开状态在同一工单刷新后保留；换身份/撤权正确清理。
- 部分失败汇总准确，取消/废弃请求不被记作成功；写入成功后读取失败只重试读取。
- 活动/历史分组、并列任务、无可见任务、未知状态、动作门控和审批跳转正确；普通任务完成入口保持可达。
- 共享消费者回归覆盖 WorkItemShell/独立审批面板，确认没有失去原有读取恢复能力或产生重复数据所有者。

### 浏览器验证

以实际权限 fixture 验证处理人、仅可读用户和无权限场景，使用 1440px 与 390px、亮/暗主题。检查统一刷新、草稿保护、Tab 切换、局部错误恢复、任务操作后更新、键盘可达及横向溢出。

业务写验证仅在隔离 fixture 中执行，不推进真实外部授权或修改共享业务数据。记录源代码与运行服务身份，不将旧部署截图作为当前实现证据。

按影响范围执行定向组件测试、TypeScript、ESLint、生产构建、Playwright 及 git diff --check。报告既有警告和未验证的浏览器/后端路径。性能通过断言刷新请求次数及未加载资源无请求验证，不新增独立性能工程。

## 6. 风险与交付边界

- 主体 loading 导致卸载是本次必须消除的问题；仅移除按钮不算完成。
- 审批消费者共享来源及共享组件默认行为容易影响其他详情，必须盘点全部调用点并删除被替代的重复路径。
- 授权空列表只能描述当前可见范围；完整流程进度保留为后续独立需求。
- 历史任务展示仅限已返回的记录，不能称为完整流程历史。
- 本文不授权部署、合并、迁移或修改共享数据库。后续实现使用独立分支/PR，生产回滚可回退该体验改动，既有后端契约不变。
