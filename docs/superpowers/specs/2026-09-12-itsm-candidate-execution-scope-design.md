# 候选执行范围与启动生命周期设计

状态：accepted（维护者已确认书面设计；尚未实现）。

所有者：Agent A；环境实施：Agent B。代码证据基线：`d7470a32dbb87acc9b5e4d9a895a146410723561`；准入证据：T2 revision-2 `a0ad4617c6467df87f6bf942d5969004c60ca21c`。本文为[候选交付设计](2026-09-12-itsm-candidate-integration-delivery-design.md)的 B2 前置设计，不表示实现或运行通过。

## 1. 目标、方案与边界

在恢复的真实业务副本上读取历史数据，只允许本轮新建验收记录及其归属明确的子任务发生业务写入。继续使用原有 WorkItem、专业生命周期、BPMN、队列与 RBAC，不增加第二套执行引擎。

方案比较：全部停用消费者不能完成 G2；另建租户需要重建业务配置，不能充分验证真实源配置；选择持久化执行范围和原入口约束，承担逐入口接入与测试成本。新范围只是执行许可的附加限制，不授予权限、不决定业务状态，也不依赖时间戳、ID 大小、标题前缀或调用方自报标签判断归属。

不处理 R(038)、历史 backfill、企业连接器实发、通用任务重放平台、生产部署、旧 worktree 清理。共享历史流程/目录/分类/角色等配置在候选应用中只读使用；修改这些历史配置不属于验收写入权限。若必需业务配置缺失，形成具名的新配置准备项和依赖审阅，不能在启动时补默认数据。

## 2. 权威模型与许可来源

新增受控迁移定义执行范围及 WorkItem 成员关系：范围包含 UUID、目标部署标识、tenant_id、状态（active/closed）、创建者、创建时间；成员以 (scope_id, work_item_id) 唯一，引用现有 tickets，记录归属创建的审计信息。WorkItem 的 tenant、身份、业务状态仍只在现有权威模型维护；成员不是业务字段副本。数据库约束/受限写入路径保证范围 tenant 与 WorkItem tenant 相同。

范围由受限维护命令在隔离副本显式建立，API/Worker 无建范围、重新启用关闭范围或接纳历史 WorkItem 的权限。候选配置固定 deployment_id 和 active scope 清单，载入时核对数据库记录；不存在、关闭、跨部署、为空或格式错误即拒绝写入就绪。一个租户只对应一个本轮活动范围。修改范围配置要求停用执行入口并重新准入，不热更新。

新建 WorkItem 的服务事务从可信运行配置和已认证租户取得范围，原子完成 tickets、专业扩展及成员登记；事务失败全部回滚。数据库以 tickets INSERT 触发的窄授权成员登记保证只接纳本事务新建行：运行角色不能直接 INSERT/UPDATE/DELETE 成员；触发器读取事务局部的可信范围设置并检查部署、tenant、active 状态，缺失或不匹配拒绝候选创建。触发函数固定 search_path、限定对象、不得被运行角色直接调用，不承载任何专业业务规则。标准部署按显式运行身份配置不登记候选成员，不以设置缺失自动判为标准模式。不存在面向已有 ID 的收编 API/CLI，不接受 HTTP scope header 作为许可。衍生 WorkItem 同样新建并登记，关联不能使历史 WorkItem 自动获得许可。范围检查不能替代用户身份、RBAC、RLS、版本及专业生命周期检查。

子记录通过已有结构化 WorkItem/process/task 关系解析归属；没有可验证关系的任务必须保持禁用或在生产者处补充具有结构化约束的归属，不能从任意 JSON、日志或对象命名猜测。数据模型没有结构化引用的入口，须在实施计划逐项指明新增引用与迁移，不能到运行时回退全量。范围关闭后不得产生新领取或新副作用；关闭操作先停止并等待所有执行进程退出，再关闭记录，不能用一次检查声称可撤销已经发出的外部请求。

## 3. 构造与运行生命周期

沿现有 bootstrap 的 application/run 分离完善：配置与依赖只读校验 → 构造服务 → 就绪判定 → 启动获准消费者。构造阶段不得启动 goroutine、订阅、建 bucket、建表/扩展、部署模板、LoadAll 连接器或运行一次扫描。所有后台任务使用应用生命周期 context，退出时取消并等待，然后关闭 DB/Redis。

schema/扩展由唯一迁移入口负责；对象 bucket 由 B 的显式资源准备负责。附件配置选定唯一后端，初始化失败拒绝依赖就绪，不自动切换本地目录。默认流程/绑定不在 API 启动时生成；源已有配置只读核验。连接器元数据读取与实例启动拆开；候选不装载历史企业秘密，不实例化未获准连接器。

部署配置显式区分标准运行与受限候选运行；两种模式共享同一服务/队列路径。候选启动清单记录每个能力为 disabled 或 scoped；未知能力、拼写错误、缺少范围实现而配置 scoped 均拒绝启动。关闭能力是部署配置，不将被关闭的业务步骤报告成功。标准运行模式仍需走统一无副作用构造和显式生命周期，不保留旧的隐式自启分支；现有部署所需配置变更须在运行手册列出，不能默默改变既有线上配置。

## 4. 各执行入口的约束

| 入口 | 必须控制的位置 | 初始候选要求 |
| --- | --- | --- |
| 通用 outbox | 未知类型标记、claim、租约回收、attempt、retry、终态更新全部带相同范围条件；领取事务内校验 | workflow start、内部领域事件接入 scoped；外部投递保持明确 blocked 或专属接收端 |
| BPMN callback、通知、独立 KAF Worker | poll/claim/recovery 即过滤，执行及回执再校验 tenant/owner/claim token | G2 所需路径必须 scoped；任何缺口阻塞对应 G2 |
| SLA/escalation | 查询仅选择本轮成员；后续事务和发事件保持归属 | 使用真实新建 WorkItem 验证周期，不遍历旧记录再跳过 |
| Redis Stream 审计/webhook | 新事件写入 deployment/scope 命名空间；订阅者仅订阅该空间并核对持久化归属 | 不在旧 stream 上建组、读取、ACK/NACK、trim；复制历史 stream 保持原样 |
| embedding 初始/定时扫描 | 无 WorkItem 归属的知识写入不授予范围 | 初期 disabled；历史知识检索只读，embedding 写入不计为通过 |
| 连接器恢复/轮询、发现、CMDB import/export | 历史配置实例化与请求触发异步均受能力限制 | 初期 disabled；不以网络失败代替范围控制 |
| 内存 tool queue、请求异步任务 | enqueue 前鉴权与归属，执行前复核；不自动承接历史对象 | 只开放已列入 G2 的有归属动作，未知工具明确拒绝 |
| 工单读取触发的飞书同步等 | 业务副作用服务入口校验，GET 本身不得绕过 | 历史读取允许，外部同步不触发；操作结果明确表达未执行 |
| API 业务修改、关联、评论、附件 | 服务事务内校验全部被写入主体，而非只保护路由或父记录 | 历史编辑拒绝；新旧关联若会写历史端则拒绝；新记录附件进入专属存储 |

SQL 过滤必须位于 UPDATE/claim 的原子语句或同事务锁保护边界内，不能先读全队列再修改历史 lease。未知历史事件也不能被 BlockUnknownPendingEventTypes 改成 blocked。历史消息无范围时只保全；新命名空间内遇到未知类型显式失败并产生独立诊断，不伪造成功 ACK。失败不得扩展为重读旧 stream 的恢复策略。

新事件的 scope 信息来自已验证生产者，不信任 payload 自报值；订阅时验证 envelope 与权威成员及 tenant 一致。只有带明确主体的事件可发布到受限空间。命名空间是传输隔离，不替代业务归属和鉴权。同一事件不同时发布到旧 topic 与新 namespace。

候选 API 对非验收必需的写路由默认拒绝；被开放的路由仍必须在所属服务校验范围，以覆盖 CLI、Worker、内部调用。登录、刷新、注销及必要的追加审计属于单列基础能力，按鉴权设计运行，不借此允许改历史用户/角色/连接器。只读页面可能留下新的访问审计，但不得修改既有审计行；是否允许追加必须在启动清单声明。

## 5. 历史保全与失败语义

启动前冻结受保护记录 ID 清单及内容摘要。历史业务行、关系、流程实例、定义/绑定、队列状态/attempt/lease、审计行、知识/vector、旧 Stream 内容和消费组均须不变。允许新建记录、新成员、新子任务与具名追加审计；正常编号分配导致的 sequence 前进单独记录，不把新增数据当历史摘要变动，也不能忽略 UPDATE/DELETE。

Redis 键按绝对到期核验，自然过期可解释；不重置期限。失败只写新范围内的原有失败/重试状态或隔离诊断，不能为“修复”而修改历史任务。范围不可确认返回明确拒绝/基础设施不可用，禁止静默跳过后返回业务成功。就绪输出只含能力状态和脱敏范围指纹，不暴露业务数据或秘密。

## 6. 验证与交付

测试先证明现有风险：构造启动消费者、未知历史 outbox 被改状态、GET 异步副作用。实现后使用隔离 PostgreSQL/Redis 和真实受限角色，验证：

1. 构造和启动前准备不产生任何未经声明的 DB/对象/Stream 写入。
2. 同租户历史、新验收、其他租户记录混排；包含历史 unknown、pending、expired lease、retry、callback、notification；所有历史行/队列字段均不变。
3. 新建 base/extension/member 原子性；伪造 scope、跨租户、引用历史对象、未登记子任务、直接调用服务均拒绝。
4. 原 worker 的领取、执行、重试、幂等、崩溃恢复及关闭等待均在范围内；并发领取不能扩大范围。
5. 老 Stream 不产生任何组/消费状态变化，新 namespace 的真实内部审计可完成；未知新事件不会报告成功。
6. 新 WorkItem 经过真实 BPMN/API/Worker/SLA 路径，外部动作仍 blocked 或使用声明的测试接收端；完整周期及重启后历史摘要不变。

禁止仅以 mock scope 返回 true 证明门禁。新 schema 只增加表/约束/必要结构化引用，不补历史归属，不改历史 SQL/checksum。注册前重新核对迁移序号和依赖，不占用或执行 R(038)。受限角色不得删除成员或任意登记历史对象。

实现计划必须把上表每个入口映射到文件、生产者、领取查询、归属关系和测试；遗漏任何自动写入者不得放行应用。A 单独分支/worktree 实现并独立审阅，集成后固定新 CandidateSHA；B 重核新增迁移、范围准备和实际受限角色，再按 T3 执行。能力禁用不能缩减已批准 G2：若必需项仍 disabled，T4/T5 保持 blocked。
