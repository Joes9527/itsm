# 工单详情处置工作台（Ticket Detail Workbench）重构技术设计规范

## 1. 背景与目标

### 1.1 背景
当前工单详情页（`TicketDetail.tsx`，对应路由 `/tickets/[ticketId]`）存在以下体验与交互问题：
1. **单列长页面垂直堆叠严重**：信息层级平铺，用户需上下滚动数屏才能浏览完诉求、表单、SLA 与操作按钮；
2. **操作动作栏埋层过深**：核心动作（批准/拒绝/分配/编辑/抄送/删除）放置在页面中下部，工程师进入页面无法第一时间完成处置；
3. **宽屏利用率低**：右侧留白过多，信息密度不足；
4. **功能完整度**：需确保在提升视觉质感的同时，原有的所有弹窗、权限动作门控（`ticket.actions`）、动态自定义字段、SLA 倒计时及底部 5 维 Tabs（评论、附件、审批链、流转历史、关联）100% 零遗漏继承。

### 1.2 目标
- 将工单详情页升级为**现代专业运维处置工作台（Operational Workbench）**；
- 采用 **左侧主信息流（8列） + 右侧高密度运维工具箱（4列，支持 Sticky 悬浮）** 的双栏响应式架构；
- 遵循 `frontend-design` 规范：统一主操作暖橙色（`bg-orange-500`）与次级幽灵线框按钮体系，全宽自适应，消除多余灰底留白；
- **保障原有业务逻辑 100% 不变**。

## 3. 功能映射与兼容性保障（零丢失）

### 3.1 动作控制台与权限（Action Console）
- **位置**：置于页面 Header 右侧，始终保持最高视觉可见性；
- **继承逻辑**：
  - `批准`：`onClick={handleApprove}`, `loading={approving}`, `disabled={!ticket.actions?.approve?.allowed}`, `title={ticket.actions?.approve?.reason}`；
  - `拒绝`：`onClick={handleReject}`, `loading={rejecting}`, `disabled={!ticket.actions?.reject?.allowed}`；
  - `转派分配`：`onClick={handleAssign}`, `disabled={!ticket.actions?.assign?.allowed}`，唤起 `AssignModal`；
  - `编辑`：`onClick={handleUpdate}`, `disabled={!ticket.actions?.edit?.allowed}`，唤起 `EditModal`；
  - `抄送`：`onClick={() => setCCModalVisible(true)}`, `disabled={!ticket.actions?.cc?.allowed}`，唤起 `CCModal`；
  - `删除`：`onClick={handleDeleteClick}`, `disabled={!ticket.actions?.delete?.allowed}`，唤起 `DeleteModal`；
- **按钮样式规范**：
  - 主操作（批准）：`bg-orange-500 hover:bg-orange-600 text-white shadow-xs`；
  - 次级操作（拒绝、分配、编辑、抄送）：`bg-white hover:bg-slate-50 text-slate-700 border border-slate-200 shadow-2xs`。

### 3.2 弹窗交互完整保留（Modals）
原组件内的所有受控弹窗完全保留并复用：
1. **AssignModal**：包含 `assignForm`, `assigneeId` 下拉搜索（`users` 列表）、`comment` 备注；
2. **EditModal**：包含 `editForm`, `title`, `description`, `priority`, `customFields`（动态字段编辑与校验）；
3. **CCModal**：包含 `ccForm`, `userIds` 选择、通知渠道多选（站内信/邮件/短信/飞书/钉钉/企微/Webhook）及抄送备注；
4. **DeleteModal**：二次防误删确认对话框。

### 3.3 服务目录与资源交付（Service Catalog & Provisioning）
- 当 `ticket.source === 'service_catalog'` 时触发；
- 调用原有的 `<ServiceRequestPanel ticketId={ticket.id} />`，保留交付任务列表、开始交付按钮及审批链的联动。

### 3.4 五维标准 Tabs 协同流
底部的 Tabs 完整复用已封装的领域子组件：
1. **评论 Tab**：使用 `<CommentPanel />`，包含 `UserSelect` 搜索 @提及某人、`仅内部可见` Checkbox 开关与评论修改/删除能力；
2. **附件 Tab**：使用 `<AttachmentPanel />`，支持文件上传、下载与图片缩略图；
3. **审批链 Tab**：集成 `<ServiceCatalogApprovalChain />` 与 `<ApprovalWorkflowPanel />`；
4. **历史 Tab**：集成 `<HistoryTimeline />`（读取变更审计日志与历史快照）；
5. **关联 Tab**：集成 `<RelationPanel />`。
