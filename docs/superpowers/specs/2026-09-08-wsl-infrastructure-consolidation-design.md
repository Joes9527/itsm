## 1. 背景与权威来源

KAF 为 `/Users/julian/development/agent-control-plane`，ITSM 为 `/Users/julian/development/itsm`。双方通过 Intake、签名委派与任务范围结果 API 协作；ITSM 拥有业务与 BPMN 状态，KAF 拥有会话、Procedure 和执行账本。

当前拓扑参考 [本机开发环境](../../development-environment.md)，操作纪律参考 [开发指南](../../DEVELOPMENT_GUIDE.md) 与 [Coding Agent 工程规范](../../agent-engineering-governance.md)。2026-09-08 文档快照记录 ITSM / KAF 使用不同 PostgreSQL、Redis 实例，KAF 开发共用 acp MinIO；这是盘点线索，不能直接作为迁移目标清单。

本设计是跨仓库整合决策的权威来源。KAF 文档引用本设计，不复制维护第二份决策。原有生产 Worker 设计与本设计范围不同，继续有效。

## 2. 目标、范围与替代方案

目标：减少重复开发实例，统一连接、备份和运行管理；保留全部现有数据，维持领域边界；支持可核验、可回滚的停机切换。

已选择：新建专用统一开发基础设施，试迁移并验证后，在维护窗口迁入最终数据；旧实例停止应用写入并保留作为回滚来源。

未采用的方案：

- 直接复用现有 KAF 实例承接 ITSM：新增资源少，但当前 CI / 开发存储依赖复杂，扩大原实例变更影响。
- 仅统一运维、保留两套实例：迁移风险低，但不能满足 PostgreSQL、Redis、MinIO 各共用一个开发实例的已确认目标。

本次不包含生产切换、认证体系重构、业务表合并、跨数据库查询、新连接器或专业流程重构。保留既有 Qdrant 专用数据并纳入备份和验收；除非解除 CI 依赖需要隔离，不主动迁移或重建其集合。

## 3. 目标架构与访问边界

| 组件 | 目标 | 数据与权限边界 |
| --- | --- | --- |
| PostgreSQL | 一个专用开发实例 | KAF、ITSM 独立逻辑数据库与凭据；各自版本化迁移 |
| Redis | 一个专用开发实例 | 各自逻辑 DB；盘点并保留有效状态；共享实例级资源与故障影响 |
| MinIO | 一个专用开发实例 | 各自 bucket 与受限凭据；保留对象和数据库引用 |
| Qdrant | KAF 专用数据 | 保留集合、向量、payload 与检索能力；不引入 ITSM 向量存储迁移 |
| CI | 独立基础设施与数据 | 不连接统一开发库，不使用开发 bucket、持久化卷或开发凭据 |

Mac / WSL 应用接入同一组开发端点。具体宿主机端口、数据库名、Redis DB 编号、bucket、版本与容量由只读盘点确定，在实施计划及切换清单中记录；不得从旧文档默认值推定，也不在本设计中虚构资源标识。

### PostgreSQL

共用实例不改变业务所有权。KAF 不取得 ITSM 业务库权限，ITSM 不取得 KAF 业务库权限。API、Worker 使用各自既定 runtime/system 角色；迁移使用独立 migration 角色。ITSM 受限 system 客户端的既有权限模型继续有效，不能简化成共用管理员账号。

迁移须保留数据、序列、约束、索引、扩展依赖、对象归属及经核对的权限。目标版本以双方当前驱动、迁移和扩展兼容性为依据；不能顺带升级 PostgreSQL 大版本或改变 RLS 模式。导入权限前检查 PUBLIC、跨库 CONNECT 与角色继承，不照搬宽泛授权。

### Redis

独立逻辑 DB 是数据分组，不是安全隔离或资源隔离；一个实例的重启、内存耗尽和持久化故障会同时影响双方。各应用凭据与 ACL 应按命令和键用途收紧，禁止应用账号执行实例级清理。不能宣称 Redis DB 编号本身限制跨 DB 访问。

盘点缓存、会话、nonce、锁、租约、队列、Stream 消费组和其他状态；识别键名前缀、数据类型、TTL、持久化与淘汰策略，以及代码中的清理命令。实例级内存、持久化和淘汰策略须满足双方状态用途；不能因一方将 Redis 当缓存而任意淘汰另一方的执行状态。

保留永久键及仍有效的临时状态。TTL 按原绝对过期语义计算，扣除停机时间，过期凭据不得重新激活。运行中租约、锁和任务不能直接作为有效执行授权复活，应由持久化任务事实及既有恢复机制决定后续状态。

两套源实例的 DB 编号映射到目标后必须无冲突。试迁移验证数据类型、到期语义、队列顺序、消费组与待确认状态；不假定简单复制 RDB 即可合并两个实例。

### MinIO 与知识数据

KAF、ITSM 使用独立 bucket 和应用凭据，应用不得使用全局 root 凭据。保留对象键、内容、元数据、Content-Type 以及应用依赖的版本与生命周期语义；启用版本管理的源需盘点历史版本和删除标记。核验对象数量、大小和可验证的内容校验值，不能把 multipart ETag 普遍当作 MD5。

盘点 ITSM 实际附件后端，包括 MinIO 和可能的本地回退文件。任何被数据库引用的本地文件均纳入保全；文件型后端若需切换对象存储，先验证既有适配器与引用方式，不在迁移中顺带修改业务存储模型。

KAF 文档对象与 Qdrant 中的文件键、来源信息和向量集合共同核验；既有知识不能只恢复文件而丢失可检索性。开发与 CI 共用 MinIO 时，按真实调用方和对象归属拆分；不能仅按 bucket 名猜测归属，也不能迁移后删除 CI 仍在引用的对象。

## 4. 数据保全与迁移步骤

“全部保留”包括账号、权限、流程、目录、工单、会话、知识、附件、执行账本及待执行状态。完整原始备份保留用于追溯；在线恢复遵循临时状态有效期，不延长验证码或租约寿命。

### 阶段 A：只读盘点与恢复演练

1. 记录实例、版本、容量、目标网络与权限，以及所有应用、后台任务、Worker、定时任务和 CI 的连接来源。
2. 核对磁盘、内存、备份空间与迁移耗时；容量不足时不启动正式迁移。
3. 按数据库、Redis、对象、文件与 Qdrant 建立数据清单和受保护备份；备份密钥与配置不得进入仓库、日志或报告。
4. 在新开发栈恢复备份，验证恢复程序、兼容性、数据与引用关系。试迁移实例隔离生产及企业外部写入；不启动消费者、邮件通知或权限变更任务。

### 阶段 B：维护窗口正式切换

1. 记录切换清单、最终快照时间、旧/新目标标识与恢复责任。
2. 暂停 Mac / WSL 的全部写入来源，协调并检查其他开发者及 Agent。核对实际 PID、cwd、可执行文件和后台任务归属后停止；禁止按全局进程名批量终止。
3. 对运行中与未知结果任务建立清单；确认源已停止写入，生成最终备份与统计基线。
4. 迁入新栈并完成完整性与隔离验证；验证期间禁止背景消费或企业写入。
5. 更新真实有效的 Mac / WSL 连接配置和启动描述，不只修改未使用的 dotenv 示例。不重建覆盖已有专用 ITSM 修复二进制。
6. 先恢复应用再恢复消费者；按任务账本确认只存在预期消费者，避免新旧实例双重执行。源基础设施保留，旧应用不再写入。

## 5. 失败处理与回滚

- 校验失败、容量不足、权限隔离失败、引用缺失或来源未能停止写入时，不开放新环境业务写入；保留失败证据，修复或回到旧环境。
- 新环境尚未接收写入：停止新应用，恢复旧连接配置与运行实例，并验证原业务状态。
- 新环境已接收写入：先停止全部写入，保全新环境数据库、Redis 有效状态、对象和执行证据，再依据差异制定恢复操作。未核对新增数据及外部副作用前，不直接切回旧库。
- `delivery_unknown` 只按现有对账契约处理，不能强制重发；数据库回滚不能撤销已发生的企业系统写入。
- 数据备份、目标配置、运行二进制与启动参数分别保全。旧实例保留期限和最终清理在完成验收后单独由维护者决定，本任务不自动销毁。

## 6. 验收门禁

| 范围 | 必须具备的证据 |
| --- | --- |
| 数据库 | 源/目标关键表数量、主键与关系、关键记录值和序列一致；已存在的流程、目录、账号与会话可用；扩展和角色归属正确 |
| 权限 | 应用正向连接通过；跨业务库、未授权 bucket 和危险 Redis 管理命令访问被拒绝；migration 凭据不被常驻应用使用 |
| Redis | 键类型、持久状态、绝对过期语义、队列与消费状态核验；差异有明确解释，不复活过期凭据 |
| 文件与知识 | 对象与本地附件清单核验；数据库引用能下载；代表性知识可检索，来源与文件一致；Qdrant 数据保全 |
| 跨应用 | Mac / WSL 均连接目标开发栈；请求创建、审批、上下文查询与结果投影正常；待执行任务无丢失、无重复消费者 |
| 真实副作用 | VPN 加组、邮件等真实外部写入在独立受控验收步骤中明确对象、窗口与清理责任；不能由迁移恢复隐式触发 |
| CI | CI 不连接新开发数据；解除原共享存储依赖后，其所需数据与作业仍正常 |
| 回滚 | 已完成备份恢复演练；新写入后的恢复边界明确，旧实例与配置可追溯 |
| 文档 | 两仓相关文档与架构图更新完成，且与实际验证状态一致 |

基础健康不等于业务验收。每项证据记录时间、实际目标、结果和未覆盖范围；不以构建或端口可达替代业务路径验证。生产 Redis 可不迁移的决定不适用于本次开发数据保全。

## 8. 生产边界

生产环境允许维护窗口，Redis 内容可不迁移，但必须确认待执行任务与不确定外部结果的持久化和恢复安排。生产 ITSM 以独立逻辑数据库执行版本化迁移；“同步 schema”不表示复制开发业务数据或将 ITSM 表放入 KAF 数据库。角色、权限、扩展、必要业务配置和 API/Worker 连接须另行准备和验证。

本轮不执行生产数据库变更，也不推定生产基础设施已经就绪。开发整合完成不会自动关闭生产迁移与上线验收事项。
