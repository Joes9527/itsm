# 邮件建单与自动回复 UI 测试手册

状态：待执行，2026-09-14；基于当前源码核对编写，不代表 WSL 实测通过。属于[UI 全流程主手册](sslvpn-manual-lifecycle-runbook.md)第 10 节。

## 0. 邮件功能操作顺序（EM01–EM12）

按编号执行，每个功能先填数据再操作。使用主手册 OP00 的 RUN、R/R_MAIL、SUPPORT_MAIL、E、ITSM_URL 和 WAIT；邮件轮询/附件/回信分别登记实际最长观察时间。WI-MAIL 在 EM03 创建后填写真实编号，不能手工建单代替邮件建单。

### EM01：配置邮件连接器（M01）

账号：A。菜单：系统管理 → 连接器/插件市场（`/admin/connectors`）→ 市场 → 邮件（Microsoft Graph）。

| 输入位置 | 数据 |
|---|---|
| 启用 | 开启，限本轮已授权连接器 |
| 提供商 | 页面对应的 Microsoft 邮件提供商选项，核对不是其他连接器 |
| 凭据（每行 key=value） | azure_client_id、azure_client_secret，各填负责人提供的实际值；不在证据中复制密钥 |
| 设置（每行 key=value） | azure_tenant_id=批准的租户；mailbox=SUPPORT_MAIL；poll_interval_seconds=负责人交付的配置值 |

操作：找到连接器 → 打开启用配置 → 逐项填上表 → 保存 → 切换“已配置” → 刷新核对状态和实际邮箱。已有正确共享配置只核对，不重新启用或覆盖。当前轮询设置的 UI 字符串与实现读取数值存在差异，保存成功不证明间隔生效，按第 2 节记配置缺口。输出连接器状态证据和三个观察期限；不把“测试/发消息”按钮当自动回信测试。

### EM02：从邮箱发送带附件的新邮件（M02）

账号：R。入口：已批准的真实邮件客户端 → 新建邮件。

| 邮件字段 | 输入数据 |
|---|---|
| 发件人 | R_MAIL |
| 收件人 | SUPPORT_MAIL；不添加其他收件人/抄送 |
| 主题 | `RUN-MAIL SSLVPN连接问题排查测试`，展开 RUN |
| 正文 | `这是SSLVPN邮件流程测试，不代表真实VPN故障。请提供远程连接的排查指引。测试地点：上海，设备数量：1。收到后请回复本邮件。标记：RUN-MAIL-01。` |
| 附件 | `RUN-MAIL-01.txt`；文本内容为 `RUN-MAIL-01 初始邮件附件验证，无密码和真实日志。` |

操作：用文本编辑器建立上述 txt → 新建邮件逐项填写 → 通过邮件附件控件选择文件 → 检查地址/主题/正文/附件 → 发送一次 → 打开“已发送”。输出已发送时间、会话链接和字段证据；不写未完成权限申请的“已开通”结论。

### EM03：查找自动创建的工单（M03、M05）

账号：E 后 R。菜单：工单列表 `/tickets`。

| 步骤 | 功能操作 | 输入/选择 | 检查和输出 |
|---|---|---|---|
| 03.1 | E 清除列表旧筛选，在建单期限内按主题查找 | EM02 的完整展开主题 | 只有一张匹配单；没有时记超时，不手工建单 |
| 03.2 | 点击匹配工单 | 页面真实编号 | 登记 WI-MAIL 编号/URL，核对申请人为 R、标题/正文与 EM02 一致 |
| 03.3 | 查看来源和专业类型等页面可见信息 | 同一单 | 邮件通用工单，不自动是 SSLVPN 服务请求；不显示的字段记 UI 可观测性缺口 |
| 03.4 | R 正常登录自己的 ITSM，按编号搜索并打开 | WI-MAIL | R 可读原单；不能用 E 的访问成功代替申请人可见 |

### EM04：接收自动建单确认邮件（M04–M05）

账号：R。菜单：邮箱 → 收件箱，必要时垃圾箱。

操作：按 EM02 主题/真实工单编号查找系统回信 → 打开邮件 → 核对发件人、收件人、主题、正文及接收时间 → 将编号复制到 ITSM 搜索。

期望数据：正文包含 `工单 {WI-MAIL真实编号} 已创建：{EM02标题}`；主题与该编号/标题一致。必须未手动点击“发送通知”就收到，当前模板不保证有工单链接。输出自动回信实际接收证据；“通知记录发送成功”不能替代收件证据。

### EM05：回复原邮件并核对归入原工单（M06）

账号：R 后 E。入口：EM04 的确认邮件 → 回复。

| 步骤 | 功能操作 | 输入/选择 | 检查和输出 |
|---|---|---|---|
| 05.1 | 在确认邮件上点“回复”，保留会话和收件人 | 正文 `补充信息：使用1台设备，请告知需要核对的客户端信息。标记 RUN-MAIL-REPLY1。` | 不是另发同主题新邮件 |
| 05.2 | 点击发送，查看已发送 | 本次回复 | 记录发送时间和原会话 |
| 05.3 | E 刷新 WI-MAIL 评论 | 原编号 | 新增一次 REPLY1，作者/内容正确 |
| 05.4 | E 回列表搜索原主题 | EM02 主题 | 未新增第二张工单；未收到回复时按观察期限记录，不重发同一内容 |

### EM06：首封附件和回复附件分别检查（M08）

账号：E 下载，R 回复上传。入口：WI-MAIL 附件；原邮箱会话。

| 步骤 | 功能操作 | 输入/选择 | 检查和输出 |
|---|---|---|---|
| 06.1 | E 在原工单附件入口点击下载，用查看器打开 | RUN-MAIL-01.txt | 文件名/标记/中文与 EM02 相同，首封附件单列结果 |
| 06.2 | R 用文本编辑器新建第二份 txt，在原会话点击回复并附加 | 文件 RUN-MAIL-02.txt，内容 `RUN-MAIL-02 回复邮件附件验证。`；正文 `补充附件，标记 RUN-MAIL-REPLY2。` | 正确附件出现在回复草稿，发送一次 |
| 06.3 | E 刷新 WI-MAIL，查新评论和附件，下载打开 | REPLY2 与 RUN-MAIL-02.txt | 正文/附件各自记录；当前回复分支可能缺附件，缺失记 FAIL，不用首封附件成功覆盖 |

### EM07：分配邮件工单（M11）

账号：具有分派权限的 A/E。入口：WI-MAIL → 分派 → 分配工单。

操作：在“分配给”搜索并选择 E 的实际账号 → “备注”填 `RUN：请处理SSLVPN连接问题邮件流程测试。` → 点“确认分配” → 刷新详情和历史。预期负责人显示 E，分派备注可追溯；没有权限/入口记 BLOCKED，不改状态绕过。

### EM08：公开评论与评论自动通知（M09）

账号：E 后 R。入口：WI-MAIL 评论区、R 邮箱。

操作：E 不勾“仅内部可见” → 输入 `请核对本轮批准的客户端版本和连接入口，不要通过邮件发送密码。请回复确认已收到。标记 RUN-MAIL-PUBLIC。` → 提交 → E/R 分别刷新原详情 → R 在自动通知期限内检查邮箱。

分别记录：评论保存、R 页面可见、评论自动邮件通知实际收到。前两项成功不证明邮件已发送；本轮未配置对应自动通知策略则记录依赖阻塞，不在 EM09 手动补发后把本项改为自动通过。

### EM09：手动发送通知（M09 的独立子项）

账号：E 后 R。入口：WI-MAIL → 通知 → 发送通知。

| 表单字段 | 输入/选择 |
|---|---|
| 接收人 | R 的实际用户；核对与 R_MAIL 对应 |
| 通知类型 | 当前页面可用且本轮允许的类型，记录实际名称 |
| 通知内容 | `独立手动通知送达测试，请确认收到。标记 RUN-MAIL-MANUAL。` |

操作：填上表 → 提交发送 → 在“通知”列表记录本次条目 → R 在邮箱查找 MANUAL 标记。弹窗没有邮件通道选择时，不使用接口强制通道。输出手动通知实际送达结果，与 EM04 自动确认、EM08 自动通知分开。

### EM10：内部备注与接收人隔离（M10）

账号：E 后 R。入口：WI-MAIL 评论区、R 邮箱。

操作：E 勾选“仅内部可见” → 输入 `内部测试备注：仅核对邮件会话和附件，不对真实VPN故障作诊断。标记 RUN-MAIL-INTERNAL。` → 提交 → E 刷新确认保存 → R 重新登录/刷新同一单 → R 在观察期限内检查邮件正文。

预期 E 可见，R 页面和任何邮件正文均不含 INTERNAL 内容。若内部正文泄露，记 FAIL 并停止相关发送，不能删除证据后重测成通过。

### EM11：申请人确认、解决与关闭能力（M11）

账号：R 回复，E 处理。入口：EM04 原邮件会话、WI-MAIL。

| 步骤 | 功能操作 | 输入/选择 | 检查和输出 |
|---|---|---|---|
| 11.1 | R 对原确认会话回复并发送 | `已收到排查指引，本次邮件流程测试可结束；未做实际VPN连通性验证。标记 RUN-MAIL-CONFIRM。` | 不假定 EM09 手动通知也能归入原会话 |
| 11.2 | E 刷新原工单评论 | CONFIRM 标记 | 回复在 WI-MAIL，未另建工单 |
| 11.3 | E 查找并使用本版本正式解决动作 | 解决说明 `已完成邮件收发、补充信息及指引沟通测试。` | 状态与历史可查；无正式动作记 BLOCKED，不用状态编辑字段补做 |
| 11.4 | E 检查正式关闭动作，有入口才填写原因并确认 | 关闭原因 `本轮邮件流程测试结束，证据已保存。` | closed 与 resolved 分开记录；无入口关闭项 BLOCKED |

### EM12：重复检查、记录与收尾（M07、M12）

账号：R/E/A。输入：WI-MAIL、完整原主题、本轮配置变更记录。

操作：额外观察窗口后刷新邮箱与工单列表 → 按编号/主题搜索 → 核对一张原单、REPLY1/REPLY2/CONFIRM 各一次、无持续回信 → 分别汇总 EM01–11 → 仅按本轮范围恢复临时配置。

原邮件/评论/附件/工单历史保留。共享连接器不因测试结束而停用。输出工单编号、初始/回复附件结果、三类通知结果、内部备注隐私、解决/关闭结果、遗留项及负责人。观察期内无重复不等于已经证明所有协议级幂等行为。


## 1. 验收范围

所有业务动作在真实邮件客户端、ITSM 页面完成；允许 Coding Agent 操作浏览器中可见控件。不得调用 Graph、业务 API、数据库、脚本注入或浏览器内 fetch 代替页面操作。后台诊断只能解释问题，不能作为 UI 用例 PASS 的替代证据。

本流程验证：邮件发送 → 通用工单创建 → 自动确认邮件 → 原会话回复关联 → 附件 → 工程师协作和邮件通知 → 生命周期收尾。当前邮件入口创建 generic WorkItem；邮件正文写“申请 SSLVPN”不等于提交了目录自定义表单，也不代表已进入 SSLVPN 审批授权。SSLVPN 目录/KAF 流程仍按主手册单独执行。

自动建单确认、评论触发通知、工程师手动发送通知是三种不同结果，必须分别记录。收到“工单已创建”不能判定问题已解决或权限已开通。

## 2. 前置条件与角色

- R：已映射为当前租户有效用户的测试发件人，能通过邮件客户端收发邮件及登录申请人页面。
- E：可查看、处理测试工单的工程师。A：连接器管理员。O：WSL/KAF 部署与故障负责人。
- 登记测试支持邮箱、允许的发件人/收件人、用例发送数量、ITSM URL、角色及环境版本。只使用本轮允许的测试邮箱，不群发、不抄送真实业务人员。
- 部署由[WSL 部署手册](../deployment/sslvpn-wsl-deployment-and-manual-verification.md#wsl-dev-entry)独立完成。邮件收取、附件存储、异步投递及出站邮件权限需由 O 交接；不能把部署检查计入本轮 UI PASS。
- 由 O 确认轮询间隔和异步投递条件，测试前填写“建单/附件/回信”的各自最长观察时间。每次等待到期限仍未出现即记失败或依赖阻塞，保留时间，不能无限等待或重复发信制造通过。
- 凭据通过批准的安全渠道交给 A；截图不得包含密钥。实际邮箱地址与正文证据放入受限证据目录，仓库只保留脱敏结果。

### 页面配置入口

A 打开 `/admin/connectors` → “市场” → “邮件（Microsoft Graph）” → 启用配置。在现有弹窗填写“启用”“提供商”“凭据（每行 key=value）”“设置（每行 key=value）”。凭据键为 `azure_client_id`、`azure_client_secret`；设置键为 `azure_tenant_id`、`mailbox`、`poll_interval_seconds`。值由环境负责人提供，不能沿用示例账号或猜测租户值。

当前 UI 将设置解析为字符串，而轮询配置实现读取数值类型；因此页面填写轮询秒数不能证明运行间隔已生效，应记录配置生效缺口，并由 O 交付实际观察窗口，不借接口改类型补验。

保存后进入“已配置”并刷新，核对邮件连接器仍启用。若无法配置或保存不生效，记录 UI 配置缺口并交接；允许对负责人已经配置好的环境继续下游用例，但配置用例仍单独标记 BLOCKED/FAIL。页面“测试”“发消息”可能产生实际消息，不能作为无副作用健康检查，也不能替代以下真实邮件流程。

## 3. 测试数据

在邮件客户端创建主题 `RUN-MAIL SSLVPN连接问题排查测试`（RUN 为本轮标记），正文包含独有标记、问题描述及期望处理方式，例如“本轮 UI 测试，请协助排查连接问题；标记 RUN-MAIL-01”。不要包含真实密码、密钥或敏感业务附件。

用文本编辑器准备一个小型 `.txt` 文件，含同一标记和两行中文；通过邮件客户端添加附件。后续回复使用不同标记 `RUN-MAIL-REPLY1`。记录发送时刻、主题和客户端会话链接；不要手工构造邮件协议标识。

| 用例 | 操作角色与 UI 步骤 | 通过标准与证据 |
|---|---|---|
| M01 环境和配置 | A 按上述页面入口核对启用配置；R 打开测试邮箱和 ITSM，E 打开工单列表 | 保存/刷新后的配置状态、角色及约定观察期限已登记；实际收发能力由后续用例验证 |

| M05 编号与可见性 | R 从确认邮件复制编号到 ITSM 搜索并打开工单；若邮件实际包含链接，也核对其目标 | 指向 M03 同一工单且申请人可访问；当前确认模板不保证有链接，不以没有链接判失败；无搜索/访问入口则记录对应 UI 缺口 |
| M06 原会话回复 | R 在 M04 确认邮件上点击“回复”，保留收件人和会话，填写 REPLY1 标记并发送；E 刷新原工单评论 | 原工单新增一条可见回复，作者与正文正确，含本次标记；搜索未新增第二张工单。不要另建同主题邮件替代原会话回复 |
| M07 重复与回信循环 | R/E 在约定的额外观察窗口再次刷新邮箱、列表和原工单 | M02 仍只有一张工单，M06 内容没有重复追加，未出现不断互发的确认邮件。记录观察时长；此结果只证明本轮 UI 观察，不外推为所有协议级幂等测试通过 |
| M08 附件往返 | E 从工单页面打开/下载 M02 的附件，使用本地查看器比对标记和中文；R 再回复原会话并加第二个附件，E 查找新回复及附件 | 分别记录“首封附件”和“回复附件”。当前回复分支未走新建邮件的附件处理路径，回复附件可能缺失；缺失记 FAIL，不把首封附件成功算作回复附件通过。不得直接访问对象存储补交 |
| M09 工程师通知 | E 添加包含独有标记的公开评论，R 查看页面和邮箱；再在详情“通知”→“发送通知”选择实际可用类型、测试接收人并填写不同标记发送 | 公开评论、自动邮件通知、手动通知三项分别记录。自动通知应按本轮启用策略真实到达；未配置对应策略则记 BLOCKED/有理由的 N/A，不能手动补发后标自动通过。发送弹窗没有邮件通道选择时，不用接口强制通道；以实际邮箱收到的内容和收件人为证据 |
| M10 内部备注保密 | E 勾选“仅内部可见”添加另一独有标记；R 刷新工单并在观察期限后检查邮箱 | E 能看到内部备注；R 页面和收到的邮件均不含内部标记/正文。仅邮件标题通知若策略允许需单独记录；任何内部正文泄露记 FAIL 并停止该场景 |
| M11 生命周期与查找 | E/R 在页面完成分派、处理、解决及实际支持的关闭步骤，每步刷新详情、列表及活动记录；按主手册 L/Q 用例核对 | 状态、负责人和协作记录可追踪，搜索定位同一工单；resolved 不等于 closed。没有关闭页面入口则“关闭 UI”BLOCKED，不调用接口补关，也不编辑状态绕过专业动作 |
| M12 收尾与隔离 | R/E 再核对工单总数、邮箱往返、其他收件人和待处理项；A/O 按本轮范围恢复临时配置 | 无额外工单、错误收件人或持续回信；保存原邮件/附件/工单证据，不为清理而删除共享历史。列明本轮临时配置、遗留项及负责人；邮件正文未绕过目录表单、审批或触发未经允许的真实授权 |

每行中的独立断言分别记结果，不能整行只留一个笼统 PASS。浏览器等待超时先检查原邮件和原工单；不重复发送、不重新创建工单来掩盖未知结果。误投递或内部内容泄露时保留最小证据并停止相关发送。

## 5. 可选反向场景

仅在本轮范围明确包含时执行：使用另一个已获准但未映射为有效租户用户的测试邮箱发送一封邮件，预期不自动授予身份、不建立越租户关联。当前收取逻辑会跳过未映射发件人，不保证给其拒绝回信；是否应提供拒绝提示可登记产品缺口。没有获准的第二个邮箱则 NOT RUN，不使用陌生人的地址。

自动回复环路只按 M07 被动观察；不搭建两个互相自动回复的邮箱制造流量。对现有业务邮件不执行重复转发或重放。

## 6. 结果和问题记录

使用[统一记录模板](sslvpn-agent-run-record-template.md)，额外逐项填写：测试主题、发送/接收时刻、邮件客户端会话、工单编号/URL、发件人与收件人的安全引用、初始与回复附件、自动确认、公开评论通知、手动通知、内部备注隔离，以及各项观察期限。

结果只能为 PASS / FAIL / BLOCKED / NOT RUN / N/A（说明原因）。页面通知记录显示“成功”而邮箱未收到时，不能判送达 PASS；必须记录“页面显示成功、实际未收到”。运维诊断结论另附，原 UI 结果保留。
