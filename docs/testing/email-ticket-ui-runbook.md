# 邮件建单与自动回复 UI 测试手册

状态：待执行，2026-09-14；基于当前源码核对编写，不代表 WSL 实测通过。属于[UI 全流程主手册](sslvpn-manual-lifecycle-runbook.md)第 10 节。

## 1. 验收范围

所有业务动作在真实邮件客户端、ITSM 页面完成；允许 Coding Agent 操作浏览器中可见控件。不得调用 Graph、业务 API、数据库、脚本注入或浏览器内 fetch 代替页面操作。后台诊断只能解释问题，不能作为 UI 用例 PASS 的替代证据。

本流程验证：邮件发送 → 通用工单创建 → 自动确认邮件 → 原会话回复关联 → 附件 → 工程师协作和邮件通知 → 生命周期收尾。当前邮件入口创建 generic WorkItem；邮件正文写“申请 SSLVPN”不等于提交了目录自定义表单，也不代表已进入 SSLVPN 审批授权。SSLVPN 目录/KAF 流程仍按主手册单独执行。

自动建单确认、评论触发通知、工程师手动发送通知是三种不同结果，必须分别记录。收到“工单已创建”不能判定问题已解决或权限已开通。

## 2. 前置条件与角色

- R：已映射为当前租户有效用户的测试发件人，能通过邮件客户端收发邮件及登录申请人页面。
- E：可查看、处理测试工单的工程师。A：连接器管理员。O：WSL/KAF 部署与故障负责人。
- 登记测试支持邮箱、允许的发件人/收件人、用例发送数量、ITSM URL、角色及环境版本。只使用本轮允许的测试邮箱，不群发、不抄送真实业务人员。
- 部署由[WSL 部署手册](../deployment/sslvpn-wsl-deployment-and-manual-verification.md#wsl-dev-entry)独立完成。邮件收取、附件存储、异步投递及出站邮件权限需由 O 交接；不能把部署检查计入本轮 UI PASS。
- 由 O 确认轮询间隔和异步投递条件，测试前填写“建单/附件/回信”的各自最长观察时间。每次等待到期限仍未出现即记失败或依赖阻塞，保留时间，不能无限等待或重复发信制造通过。
- 凭据通过批准的安全渠道交给 A；截图不得包含密钥。实际邮箱地址与正文证据放入受限证据目录，仓库只保留脱敏结果。

### 页面配置入口

A 打开 `/admin/connectors` → “市场” → “邮件（Microsoft Graph）” → 启用配置。在现有弹窗填写“启用”“提供商”“凭据（每行 key=value）”“设置（每行 key=value）”。凭据键为 `azure_client_id`、`azure_client_secret`；设置键为 `azure_tenant_id`、`mailbox`、`poll_interval_seconds`。值由环境负责人提供，不能沿用示例账号或猜测租户值。

当前 UI 将设置解析为字符串，而轮询配置实现读取数值类型；因此页面填写轮询秒数不能证明运行间隔已生效，应记录配置生效缺口，并由 O 交付实际观察窗口，不借接口改类型补验。

保存后进入“已配置”并刷新，核对邮件连接器仍启用。若无法配置或保存不生效，记录 UI 配置缺口并交接；允许对负责人已经配置好的环境继续下游用例，但配置用例仍单独标记 BLOCKED/FAIL。页面“测试”“发消息”可能产生实际消息，不能作为无副作用健康检查，也不能替代以下真实邮件流程。

## 3. 测试数据

在邮件客户端创建主题 `MAIL-UI-<日期>-01 远程办公连接问题`，正文包含独有标记、问题描述及期望处理方式，例如“本轮 UI 测试，请协助排查连接问题；标记 MAIL-UI-<日期>-01”。不要包含真实密码、密钥或敏感业务附件。

用文本编辑器准备一个小型 `.txt` 文件，含同一标记和两行中文；通过邮件客户端添加附件。后续回复使用不同标记 `MAIL-UI-<日期>-01-REPLY1`。记录发送时刻、主题和客户端会话链接；不要手工构造邮件协议标识。

## 4. 顺序步骤与预期结果

| 用例 | 操作角色与 UI 步骤 | 通过标准与证据 |
|---|---|---|
| M01 环境和配置 | A 按上述页面入口核对启用配置；R 打开测试邮箱和 ITSM，E 打开工单列表 | 保存/刷新后的配置状态、角色及约定观察期限已登记；实际收发能力由后续用例验证 |
| M02 发出新邮件 | R 在邮件客户端发送一封上述邮件及附件到测试支持邮箱，打开“已发送” | 已发送详情显示正确收件人、主题、正文、附件和时间；只发送一次 |
| M03 自动建单 | E 在 `/tickets` 按独有主题查找，打开详情；R 在自己的工单范围查找 | 观察期限内恰有一张匹配工单；申请人与测试发件人匹配，主题/正文正确，来源邮件及 generic 类型按页面实际展示核对。页面未暴露的属性记录可观测性缺口，不用后台补证冒充 UI 可见 |
| M04 自动确认 | R 在收件箱查看系统自动回信，必要时检查垃圾箱并记录送达位置 | 无人工点击发送通知即收到确认；发件人正确，主题/正文包含与 M03 一致的工单编号和标题；记录接收时间。当前投递实现的正文是“工单 {编号} 已创建：{标题}”，不是开通成功通知 |
| M05 编号与可见性 | R 从确认邮件复制编号到 ITSM 搜索并打开工单；若邮件实际包含链接，也核对其目标 | 指向 M03 同一工单且申请人可访问；当前确认模板不保证有链接，不以没有链接判失败；无搜索/访问入口则记录对应 UI 缺口 |
| M06 原会话回复 | R 在 M04 确认邮件上点击“回复”，保留收件人和会话，填写 REPLY1 标记并发送；E 刷新原工单评论 | 原工单新增一条可见回复，作者与正文正确，含本次标记；搜索未新增第二张工单。不要另建同主题邮件替代原会话回复 |
| M07 重复与回信循环 | R/E 在约定的额外观察窗口再次刷新邮箱、列表和原工单 | M02 仍只有一张工单，M06 内容没有重复追加，未出现不断互发的确认邮件。记录观察时长；此结果只证明本轮 UI 观察，不外推为所有协议级幂等测试通过 |
| M08 附件往返 | E 从工单页面打开/下载 M02 的附件，使用本地查看器比对标记和中文；R 再回复原会话并加第二个附件，E 查找新回复及附件 | 分别记录“首封附件”和“回复附件”。当前回复分支未走新建邮件的附件处理路径，回复附件可能缺失；缺失记 FAIL，不把首封附件成功算作回复附件通过。不得直接访问对象存储补交 |
| M09 工程师通知 | E 添加包含独有标记的公开评论，R 查看页面和邮箱；再在详情“通知”→“发送通知”选择实际可用类型、测试接收人并填写不同标记发送 | 公开评论、自动邮件通知、手动通知三项分别记录。自动通知应按本轮启用策略真实到达；未配置对应策略则记 BLOCKED/有理由的 N/A，不能手动补发后标自动通过。发送弹窗没有邮件通道选择时，不用接口强制通道；以实际邮箱收到的内容和收件人为证据 |
| M10 内部备注保密 | E 勾选“仅内部可见”添加另一独有标记；R 刷新工单并在观察期限后检查邮箱 | E 能看到内部备注；R 页面和收到的邮件均不含内部标记/正文。仅邮件标题通知若策略允许需单独记录；任何内部正文泄露记 FAIL 并停止该场景 |
| M11 生命周期与查找 | E/R 在页面完成分派、处理、解决及实际支持的关闭步骤，每步刷新详情、列表及活动记录；按主手册 L/Q 用例核对 | 状态、负责人和协作记录可追踪，搜索定位同一工单；resolved 不等于 closed。没有关闭页面入口则“关闭 UI”BLOCKED，不调用接口补关，也不编辑状态绕过专业动作 |
| M12 收尾与隔离 | R/E 再核对工单总数、邮箱往返、其他收件人和待处理项；A/O 按本轮范围恢复临时配置 | 无额外工单、错误收件人或持续回信；保存原邮件/附件/工单证据，不为清理而删除共享历史。列明本轮临时配置、遗留项及负责人；邮件正文未绕过目录表单、审批或触发未经允许的真实授权 |

每行中的独立断言分别记结果，不能整行只留一个笼统 PASS。浏览器等待超时先检查原邮件和原工单；不重复发送、不重新创建工单来掩盖未知结果。误投递或内部内容泄露时保留最小证据并停止相关发送。

## 5. 可选反向场景

仅在本轮范围明确包含时执行：使用另一个已获准但未映射为有效租户用户的测试邮箱发送一封邮件，预期不自动授予身份、不建立越租户关联。当前收取逻辑会跳过未映射发件人，不保证给其拒绝回信；是否应提供拒绝提示可登记产品缺口。没有获准的第二个邮箱则 NOT RUN，不使用陌生人的地址。

自动回复环路只按 M07 被动观察；不搭建两个互相自动回复的邮箱制造流量。对现有业务邮件不执行重复转发或重放。

## 6. 结果和问题记录

使用[统一记录模板](sslvpn-agent-run-record-template.md)，额外逐项填写：测试主题、发送/接收时刻、邮件客户端会话、工单编号/URL、发件人与收件人的安全引用、初始与回复附件、自动确认、公开评论通知、手动通知、内部备注隔离，以及各项观察期限。

结果只能为 PASS / FAIL / BLOCKED / NOT RUN / N/A（说明原因）。页面通知记录显示“成功”而邮箱未收到时，不能判送达 PASS；必须记录“页面显示成功、实际未收到”。运维诊断结论另附，原 UI 结果保留。
