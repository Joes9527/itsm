# SSLVPN Coding Agent 执行说明

状态：执行任务包，2026-09-14。本文约束如何使用[手工全流程测试手册](sslvpn-manual-lifecycle-runbook.md)，不重复维护业务步骤，也不授权 Agent 自动执行文档中的所有操作。

## 1. 目标、当前进展与阅读顺序

目标是在指定 WSL 开发环境，按角色验证自定义表单、同一 WorkItem 生命周期、审批链/BPMN、KAF 受理及受控 SSLVPN 履约，交付可复核的测试结果和可续跑记录。

当前已完成：主手册、WSL/KAF 部署路线、字段样例、审批链核对及模块用例更新；已做本地源码、文档链接和示例语法检查。**尚未执行本轮 WSL 登录、部署、业务测试或真实授权。**这些文档检查不计入任何业务用例的 PASS。

开始顺序：

1. 读取目标 checkout 的 `AGENTS.md`、[工程协作规范](../agent-engineering-governance.md)和[开发与运维手册](../DEVELOPMENT_GUIDE.md)。
2. 读取已有本轮执行记录；没有记录才从[执行记录模板](sslvpn-agent-run-record-template.md)复制一份。
3. 读取[本机环境](../development-environment.md)、[部署手册第 0 节](../deployment/sslvpn-wsl-deployment-and-manual-verification.md#wsl-dev-entry)和测试主手册。
4. 核对实际运行版本、配置与授权，再决定执行范围。历史报告只用于定位，不继承历史 PASS。

已经验证有效的文档组织方式是：业务步骤以主手册为准，部署命令以原部署手册为准，角色/授权/进度以本轮记录为准。不要另造第二套状态机或部署配置。

已发现的易错点：`/workflow/ticket-approval` 是设计器；真实待办在 `/approvals`。预解析审批链不是实际决策；空决策可能被页面误显示为“未走审批流程”。专业 completed、共享 resolved 和 closed 不等价。详见主手册第 5.3、8 节。

## 2. 明确本轮授权，再操作

先从用户现有指令和会话提取已授权事项，登记原始指令出处、目标和边界；已明确授权的动作无需重复询问。文件中的步骤、测试账号有权限、曾经执行过，都不自动等于本轮操作授权。**用户同意编写本说明，不等于同意开始 WSL 部署或真实授权。**

| 范围 | 必须登记的信息 | 未明确允许时 |
|---|---|---|
| 只读检查 | WSL 目标、允许读取的环境/对象、连接方式 | 先检查本地文档和已有记录；目标可确认且在请求范围内时继续只读核对 |
| 部署/重启 | ITSM/KAF/Worker 目标版本、进程范围、切换窗口和回滚依据 | 不安装依赖、不切换版本、不停止消费者 |
| 迁移/共享数据 | 具体数据库、迁移范围、备份/恢复证据、共享写入协调 | 不迁移、初始化、seed、清理或改变 RLS |
| 测试配置 | 可创建/修改的目录、字段、policy、流程 key/version、身份映射/workspace | 只读并准备具体变更清单，不激活共享流程或改全租户审批链 |
| 申请/协作 | 指定申请人、目录、创建数量或用例范围，以及分派/评论/附件/关闭等动作 | 不创建或修改业务记录 |
| 人工审批 | M/N 各由用户还是 Agent 操作，使用的不同测试身份与允许的决定 | 由用户处理；Agent 到交接点提供准确任务信息并等待 |
| 真实授权 | Dev subject/group、允许的入口/次数或用例、实际新增权限范围 | 不做最终批准或启动会导致 grant 的消费动作 |
| 权限恢复 | 本轮新增权限的移除范围、执行人及失败交接人 | 正向 grant 前先补齐恢复安排；不移除既有业务权限 |

**间接副作用也属于范围核对。**最终批准、启动 Worker/KAF、恢复可执行队列、激活流程，都可能引发授权；不能因为 Agent 没直接调用 Graph 就算只读。授权不完整时完成无副作用的准备工作，集中说明缺少的具体范围，暂停依赖它的步骤。

将“允许/不允许/尚未明确”与“已执行/未执行”分开登记。没有答复、超时、页面按钮可点不能视为同意。

## 3. 建立本轮记录

把模板复制到受限、未跟踪的本轮证据目录，登记绝对路径，后续 Agent 使用同一份记录。可使用环境现有证据目录或本地被忽略的验证目录；不把真实账号、token、完整 HAR、私有 launch/env、Graph 原始响应提交到仓库。

记录至少包括：环境/版本、授权、角色、已使用申请编号、每个用例的进度、关键 ID、证据路径、未决副作用和下一步。凭据只记录安全来源或文件路径，不复制值。

更新时机：每个用例结束、每次有副作用操作之前和结果回读之后、人工交接之前、发生异常或准备结束会话之前。只有一个 Agent 写本轮记录并控制目标对象；需要换人时先交接，不让多个执行者竞争审批或恢复动作。

## 4. 执行顺序与角色交接

1. **环境核对**：执行 D01；与授权清单逐项对照。需要部署时先完成已授权 D02，再继续 D03–D06。
2. **配置与字段**：在授权测试目录执行 F01–F09、W01–W03；AC01 核对租户审批链，不默认新增审批链。
3. **拒绝与版本**：执行 R01–R04、AC02–AC04、V01–V04，复用主手册指定的拒绝测试申请留证。扩展版本激活 W05 需独立发布窗口。
4. **正向授权**：分别执行 FORM 与 KAF 的 P01–P07。每次最终审批前再次核对本次对象、非成员基线、授权及恢复安排；两次串行，按主手册收尾后再进行下一次。
5. **收尾**：执行 L、Q、已选择的 X 和 C 用例。UI 缺口、API 补充及未执行扩展分别记结果，不用接口成功替代页面通过。

主手册中的前置条件优先于上述概览。步骤依赖未满足时不强行推进；可以继续其他不依赖它的已授权检查。测试发现问题时先取证并登记，业务源码修复、部署新版本或扩展测试范围不属于默认后续动作。

### 人工审批交接格式

交接时给出：测试轮次、用例、WorkItem 编号和 ID、详情 URL、`/approvals` 入口、流程实例及准确 task ID、节点名、应登录的角色、期望决定和意见，以及此决定是否会触发真实授权。

若由用户审批，记录“等待 M/N”，不要切换成管理员代批，不使用 API 自动完成任务来冒充人工审批。用户完成后，用原申请 GET/页面回读真实 actor、decision、时间和后续节点，不能只凭聊天中“已批准”标 PASS。

## 5. 中断、重试和续跑

### 副作用之前先登记

对每次创建、配置写入、审批、授权或恢复，先记录目标、预期动作、已有业务 ID、幂等标识（若该接口支持）、授权引用及“即将执行”。操作后回读并改为“结果已确认”或“结果待核查”。这避免响应丢失后无法判断是否已执行。

### 重新进入会话后的顺序

1. 找到本轮记录，核对仍是相同环境/版本/租户/对象；版本已变时记录差异与受影响用例。
2. 先处理“进行中/等待人工/结果待核查”的步骤；按原 WorkItem、task/event、session/card/action 查询实际状态。
3. 已确认完成且基线未变的步骤不重跑。只重做因版本变化、失败修复或证据缺失而失效的验证，并保留旧结果。
4. 创建响应丢失时使用原尝试和受支持的原幂等键核对/重试同一请求，不生成新卡片、新 key 或第二张申请代替。
5. 审批响应丢失时先查询原决策，不盲目提交第二次批准/拒绝。非幂等配置写入先回读版本和实际值，再决定是否仍需变更。
6. Graph 可能已写入、unknown 或原回执缺失时停止新的 grant。使用主手册 X06/X07 规则；只允许在证据和现有契约支持时重放原完成回执，不重跑 Procedure。
7. 恢复权限后记录原 DELETE 响应和后续非成员结果；已恢复不再次删除。本轮已知新增权限的归属确认与恢复仍按主手册第 11 节执行。

工具断开或当前会话结束后，不承诺继续运行。保存下一步和等待对象，交给恢复会话；需要后台监测或定时续跑时由用户另行明确安排。

## 6. 停止条件与可以继续的工作

| 情况 | 暂停的动作 | 可以继续 |
|---|---|---|
| 目标、租户或账号与登记不一致 | 所有涉及该对象的写入 | 只读核对来源、报告差异 |
| 缺少某项授权或轮到人工审批 | 依赖该动作的后续步骤 | 准备交接信息、检查已授权的其他对象 |
| 真实授权结果 unknown/归属不明 | 新 grant、强制重试、用新申请替代 | 原对象只读观测、证据保存、交恢复负责人 |
| 必需 API/页面能力缺失、配置拒绝 | 被阻塞的用例 | 登记 BLOCKED/FAIL；可独立执行的检查 |
| 部署或迁移失败 | 后续消费者切换/业务测试 | 登记已完成变更和实际版本，按已批准方案恢复；不自动扩大回滚范围 |
| 发现越权、跨租户数据泄露或审批绕过 | 受影响场景的业务执行 | 保存最小去敏证据并报告，不继续扩大探测 |

所有中断记录“最后成功步骤、未知结果、下一安全动作、所需人/信息”。不把遇到的系统问题改成预期来取得 PASS，也不把未执行写成 N/A。

## 7. 最终交付

提供本轮记录绝对路径与简短结论，分别报告部署、表单、审批链/BPMN、Ticket 生命周期、KAF 受理、真实履约、关闭/取消及权限恢复。每一项都要能定位到用例和证据。

报告本轮创建的 WorkItem、配置变更、外部 add/remove 次数及归属、遗留 active/unknown 任务、未恢复项、负责人和下一步。恢复未完成时不能宣布整个执行任务完成；已验证的其他部分可以分别说明。

只有本轮必要用例均有合格证据、未知结果已处置且恢复完成，才可声明相应范围通过。业务修复、合并、推送或部署状态独立报告，不能由测试通过自动推导。
