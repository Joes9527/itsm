# UI 全流程测试手册：SSLVPN、邮件建单与自动回复

状态：UI 验收手册，2026-09-14 修订。按用户确认，**本轮通过 ITSM/KAF 页面和真实邮件客户端操作，不做 API 验收，不以接口或数据库结果替代 UI 通过**。ITSM 源码参考 `a25e108d2`，KAF 本地参考 `dfe304da`；本次为文档及静态核对，没有执行 WSL 测试或发信。

给 Coding Agent 执行前，先读[执行说明](sslvpn-coding-agent-execution-guide.md)，复制[执行记录模板](sslvpn-agent-run-record-template.md)。详细邮件步骤见[邮件建单与自动回复 UI 手册](email-ticket-ui-runbook.md)，它是本轮必测部分。

具体账号候选、角色/审批组、菜单路径及 WSL 入口见[账号与菜单清单](sslvpn-ui-accounts-and-menus.md)。历史账号必须先在本轮环境确认有效。

## 0. 按功能顺序操作（执行入口）

本节从准备数据开始，按功能编号逐项执行。每个功能都列出账号、菜单、操作、输入和保存后的检查；后文用例表提供额外判定规则。SSLVPN 提供贯穿各功能的统一测试数据。

**执行顺序：**OP00 数据 → OP01 环境 → OP02 登录 → OP03 用户 → OP04 角色 → OP05 组成员 → OP06 目录基础信息 → OP07 自定义字段 → OP08 流程版本 → OP09 审批链 → OP10 目录绑定/启用 → OP11 填表校验 → OP12 提交/查找 → OP13 分派/协作 → OP14 一级审批 → OP15 二级审批 → OP16 履约结果 → OP17 关闭检查 → OP18 KAF 入口 → OP19 拒绝 → OP20 版本/取消 → OP21 邮件 → OP22 恢复。

某功能缺少 UI 时记录 BLOCKED，写明受阻的下游编号；可以使用负责人已准备的前置继续独立功能，但原配置功能仍不通过。页面行为错误记 FAIL。禁止改用 API 补成通过。

### OP00：建立测试数据表

操作人：测试执行者。入口：[本轮执行记录](sslvpn-agent-run-record-template.md)。先填写实际值，再执行后续功能；下文大写代号都从本表取值，不要原样填入页面。

| 代号 | 数据/填写规则 | 后续用途 |
|---|---|---|
| RUN | `SSLVPN-UI-YYYYMMDD-01`，换执行日，重跑用新序号 | 目录/标题/评论/附件的唯一标记 |
| ITSM_URL / KAF_URL | 负责人确认的实际前端地址 | 浏览器入口；历史端口 3001/5173 不是本轮实测 |
| A / R / M / N / E | A/E 用负责人指定账号；R/M/N 先查 `end_user_test` / `supervisor_test` / `lixin_test`，以当前确认结果为准 | 登录及分派；密码只登记安全来源 |
| R_NAME / R_MAIL / SUPPORT_MAIL | R 实际姓名、真实发件邮箱、测试支持邮箱 | 联系人/邮件收发，不能用 fixture 的 example.com 地址 |
| DEPT | `研发支持组`，本轮演练表单值 | 部门下拉框，不修改实际组织关系 |
| EMPLOYEE | `UI-EMP-001` | 自定义工号，不改变认证身份 |
| POLICY_LABEL | 负责人确认的固定 Dev 策略显示名 | 表单审阅信息，不凭输入改变实际授权组 |
| TARGET | 负责人批准的 Dev 服务名称 | 目标服务字段，不复制历史生产网段 |
| DURATION | 页面已有且获准的期限，优先“30天”；同时记录页面实际标签/编码（若可见） | 自定义授权期限；不新造不受 policy 支持的选项 |
| USE_DATE | 执行日后一天，填写具体年月日 | 计划日期，不等于授权到期时间 |
| REASON | `因出差值班，需要使用1台设备远程访问本轮批准的内部测试服务，申请临时SSLVPN权限。` | 申请理由/业务事由 |

| C-FORM / C-EXEC | OP06 输出的禁用字段测试目录 / 已准备的可履约 SSLVPN 目录名称及页面链接 | 不把普通字段测试目录当作 access 目录 |
| WORKFLOW_VERSION | OP08 查到的本轮实际流程版本 | 目录绑定及新实例核对 |
| WAIT / RESTORE | 实际最长观察分钟数、恢复负责人和批准的固定 Dev 用户/组引用 | 超时判断与权限恢复 |
| WI-FORM / WI-KAF / WI-MAIL | 创建后填写真实工单编号/详情链接，初始为空 | 同一流程各功能持续使用原编号 |

## 1. 范围与执行路线

两条路线共享工单查询、协作和生命周期检查，但不强行合成同一个专业流程：

- **SSLVPN 路线**：管理页面配置字段/流程 → ITSM 表单或 KAF 对话发起 → 两级审批 → KAF 履约 → 页面查看结果 → 关闭能力检查 → 历史/权限恢复检查。
- **邮件路线**：真实邮箱发信 → ITSM 自动建单 → 邮箱收到自动确认信 → 回复原邮件 → 原工单追加内容 → 工程师处理及通知 → 关闭能力检查。

当前邮件入口创建通用工单；不会因为主题写了 SSLVPN 就自动成为目录服务请求或获得授权。SSLVPN 是 `service_request_item`，邮件工单是 `generic`。前者的一个专业扩展与一个 WorkItem 共同创建，不另建第二张 Ticket 接续审批。

### 1.1 UI 验收规则

1. 人工或 Agent 通过可见页面点击、输入、上传、下载、搜索和刷新。浏览器自动化可以操作真实控件；不得直接调用后端接口、执行浏览器脚本发请求、注入登录态、改表或调用 Graph 来代替用户动作。
2. 邮件必须从实际测试邮箱客户端（Outlook 网页/桌面或其他已确认客户端）发送、回复与接收。不能以模拟发信、接口回执或日志中的 sent 作为邮件送达证明。
3. 页面缺少必需操作：记录 BLOCKED；页面行为/内容错误：记录 FAIL。可以在环境负责人已准备好的独立配置上继续其他 UI 用例，但不能把原配置用例补记 PASS。
4. 网络请求、日志、数据库与运维命令可由有权负责人另行排障；排障修复后必须回到 UI 重测。本手册没有 API 补充通过路径。
5. 部署是独立前置工作。保留[WSL/KAF 部署参考](../deployment/sslvpn-wsl-deployment-and-manual-verification.md#wsl-dev-entry)，测试员从负责人交付的可用环境开始，不因阅读该文档自动执行部署。
6. PASS 必须有本轮页面/邮箱证据。未执行记 NOT RUN；依赖不齐记 BLOCKED；不适用需写理由；有功能缺口不能标 N/A 来规避。

## 6. SSLVPN 两个受理入口与拒绝（R01–R04）

### 6.1 ITSM 表单、主管拒绝

1. **R01.1 / R**：在本轮目录完成字段校验，标题含 FORM-REJECT，点击一次“提交申请”。记录回执编号和详情链接；提交结果不明时停留原申请，不新建替代。
2. **R01.2 / R**：从 `/tickets` 清除旧筛选，查原编号，核对申请人、五类字段和待审批状态；不应出现“已授权”。
3. **R01.3 / M**：在 `/approvals` 按“业务单据”编号和流程 key 找“上级领导初审”，打开关联详情核对原表单，再返回“领取”。
4. **R01.4 / M**：点“拒绝”，先留空意见，确认被拦截；填写“本轮 UI 测试：主管拒绝”后提交。
5. **R01.5 / R/N/A**：刷新原详情、二级待办和流程实例。应显示拒绝/拒绝终点，无二级可办任务和授权完成展示；原字段和拒绝意见保留。

审批中心当前只取前 100 条任务再筛待办，找不到时先使用页面可用筛选/刷新和工单实例入口。仍找不到记 UI 可发现性缺陷，交负责人排障，不通过任务接口取 ID 后代批。

### 6.2 KAF 对话、网络运维拒绝

1. **R02 / R**：在目标 workspace 新会话申请本轮目录，提供五类字段。核对确认卡、身份、用途、期限，确认一次；打开 ITSM 详情核对同编号和字段。KAF 不能收集/展示必填内容时记 UI 缺口，不用隐藏请求补值。
2. **R03.1 / M**：在审批中心核对关联原单，领取并批准，填写可识别意见；随后 N 才应看到二级任务。
3. **R03.2 / N**：打开原表单核对，领取并拒绝，填“本轮 UI 测试：网络复审拒绝”。
4. **R04 / R**：原 KAF 卡刷新，离开并重开会话；ITSM 原详情刷新。两端显示同一申请拒绝，无“权限开通成功”。

拒绝流程实例可能技术上显示“已完成”，不能把这个词当成授权成功。没有 UI 能观察外部成员关系时，外部无授权这一项记录“UI 不可验证”，不以后台日志补记 UI PASS。

## 8. Ticket 生命周期与关闭（L01–L06）

专业“已完成”、共享已解决和已关闭不同。当前 SSLVPN 模板无额外用户确认关闭节点，详情也无独立关闭/重开按钮；本轮要测出这项 UI 缺口，不能改用接口把工单关掉。

| 用例 | UI 操作 | 预期 |
|---|---|---|
| L01 | 完成后刷新详情、审批链、历史、字段和附件 | 原数据及结果可追溯，不把专业完成写成已关闭 |
| L02 | 检查真实页面的正式关闭动作和允许角色 | 没有动作记 UI BLOCKED；有动作则只在无活动履约/unknown 后进入 L03 |
| L03 | 使用本版本已提供的正式关闭 UI，填写反馈并确认，再查看状态与历史 | 已关闭、关闭时间/操作记录可见，字段和授权结果保留；没有 UI 则 BLOCKED，绝不使用状态编辑下拉框绕过专业流程 |
| L04 | 在已有独立 closed 测试记录上检查动作和只读提示 | 当前 closed 为终态；有重开按钮时记录与领域约束是否冲突，不对原授权单尝试重新授权；无按钮不是接口拦截的证明 |
| L05 | 新建未最终批准申请，申请人查找正式撤回/取消动作并按 UI 操作 | 若缺入口记 BLOCKED；若可取消，待办、流程、状态一致；申请表“取消”返回目录不算撤销已提交记录 |
| L06 | A 在专用未批准实例点击“终止”，核对确认框后确认 | 管理员终止与申请人取消分开记录；待办不可继续、专业展示与历史一致 |

SLA 在页面核对绑定策略、剩余时长、提醒和终止计时；不修改时钟/数据库造超时。只有完成长时观察才记超时用例 PASS。通知通过通知页及真实接收端核对；评论保存不自动等于邮件已发送。

| X02 | 用非审批人测试账号打开审批中心和原单 | 没有可执行的越权审批；若出现允许动作仅在授权负向对象上点按验证，不调用决策接口 |
| X03 | 环境负责人独立准备消费者暂停场景时，测试员只观察 UI；本轮不主动停共享 Worker | 等待期间不假成功，环境恢复后原单继续；未准备该场景记 NOT RUN |
| X04 | 尝试从 UI 保存缺必要配置的专用目录或提交已变更目录 | 页面明确拒绝，不绕过审批；缺入口按 UI BLOCKED |
| X05 | 仅在 UI 能配置的专用无外部权限流程中验证未知任务 | 发布拒绝或执行可见阻塞，不能静默跳过；不手工改 XML/接口造测试 |
| X06 | 自然出现“结果未知”时保存原详情、时间、任务可见信息 | 不显示授权完成，不通过重试/新申请再次授权；交 O 处理 |
| X07 | 检查是否有明确、安全的原回执恢复 UI | 没有入口记 UI BLOCKED；仅刷新页面不算回执重放，删除原 API 重放步骤 |

## 10. 邮件建单与自动回复（M01–M12，必测）

按[邮件 UI 手册 EM01–EM12](email-ticket-ui-runbook.md)逐功能操作并记录输入数据与输出，再核对 M01–M12 的对应断言。邮件单 WI-MAIL 与权限单分别登记。执行全部步骤，使用真实邮箱 UI：连接器可见配置 → 发带附件的测试邮件 → 列表发现工单 → 收到自动确认信 → 回复原确认信 → 原工单出现回复 → 工程师协作/通知 → 关闭能力检查 → 收尾。

邮件正文不是自定义表单答案。发送“办公地点=上海”不等于系统已把它映射到结构化字段；不能用邮件创建的 generic 工单冒充 SSLVPN Requested Item。

## 11. 收尾与恢复（C01–C04）

| 用例 | 操作 | 证据 |
|---|---|---|
| C01 | 用获准目录管理 UI 核对固定对象与本轮权限前后状态；核对本轮邮件/工单清单 | 区分本轮新增权限、已有权限和 unknown；有来源记录 |
| C02 | 由获准恢复人在已确认的权限管理 UI 移除仅属于本轮的新增权限，再刷新成员列表 | UI 操作与移除后截图；如只能运维恢复，交 O 独立执行并记录“运维恢复”，UI 恢复用例仍 BLOCKED，不重复删除 |
| C03 | A 通过管理 UI 禁用专用测试目录或恢复原流程绑定，确认不会影响运行实例；邮件连接器若共享不随意停用 | 配置前后截图；原工单、评论、附件和邮件历史保留 |
| C04 | 重新登录查看历史与本轮遗留项 | 无未交接的活动/unknown 任务；权限恢复不改写原成功结果；收件箱无持续回复风暴 |

正向 grant 前必须明确恢复负责人。出现 unknown 也需要核对可能已经产生的权限；不能删除无归属的已有权限。

## 12. UI 测试记录与结论

从[本轮记录模板](sslvpn-agent-run-record-template.md)逐用例记录。每项至少有“角色、页面/邮箱、操作、预期、实际、结果、截图/邮件引用、问题负责人”。

总结分别报告：环境前置；目录/字段 UI；审批链/BPMN UI；FORM/KAF 两个受理入口；履约展示与可观察外部效果；邮件建单/自动回复/回复归单/附件；工单关闭/取消；恢复。不能将部署成功、后台排障通过或接口响应合并成 UI 通过。

必需用例被阻塞时，结论写“已完成部分 UI 验证，以下步骤被阻塞”，列明缺入口或缺配置。明确“未通过 UI 完成”比绕过页面跑通更符合本轮目标。
